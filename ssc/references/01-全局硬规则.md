# 全局硬规则

## 总控原则

- 本 Skill 只负责前期链路、真值、引用、门禁和 QC，不直接生图或生视频。
- 所有动作必须按 `影视工业体系数据中心 -> 故事板概要 -> 场景调度表 / 空间真值 -> 视觉资产 -> 舞台定位图 -> 黑白 3x3 分镜 -> 视频提示词列表.md -> 视频生成` 顺序执行。
- 不允许跳过双 MD、空间真值、视觉资产或舞台定位图直接做黑白分镜 / 视频提示词。
- 每个制作动作前必须通过 `question` 工具授权；一次授权只覆盖当前动作。B7 可一次覆盖增强选择、确认 `视频提示词列表.md` 和同轮视频生成。用户原话包含“全自动”时，视为全程自动授权：常规制作动作、推荐项选择、外部 Skill 加载和连续推进不再逐次弹窗，统一按本 Skill 推荐方案执行；但 `[E06: Reference Resolve Failure]`、`[E07: Required Reference Missing]`、模型不可用 / 需换模型、连续 3 次 FAIL、缺少剧本 / 关键资产、法律或安全风险仍必须通过 `question` 高危弹窗请求人工决策。

## 命名与隔离

- 核心文档标题必须是：`影视工业体系数据中心 — [集数][段落编号][场景名]`、`故事板概要 — [集数][段落编号][场景名]`、`场景调度表 — [集数][段落编号][场景名]`、`空间真值调用中心 — [集数][段落编号][场景名]`。
- 禁止创建或读取不带段落锚点的旧名，如 `故事板概要`、`场景调度表`、`空间真值调用中心.md`。
- 所有中间资产必须绑定同一个 `<集数 + 段落编号 + 场景名>` 和 `script_source_node`。
- 旧节点、旧参考图、旧 `image_path` 必须标记 `[DEPRECATED_OLD_VERSION]` 并从 ACTIVE 池隔离。

## 运行状态账本

每个 `<集数 + 段落编号 + 场景名>` 必须在 A0 内维护 `[SSC_RUNTIME_LEDGER]`，作为全链路唯一状态账本。账本必须包含：`script_source_node`、`active_core_docs`、`active_asset_pool`、`deprecated_asset_pool`、`question_authorization_log`、`external_skill_load_log`、`stage_qc_log`、`fail_counter_by_stage`、`lineage_audit_chain`、`latest_success_checkpoint`、`chain_freeze_manifest`、`core_doc_freeze_records`、`dispatch_payload_freeze_records`、`video_task_mapping`。任何新增 / 重做 / 修复 / 合并 / 剪枝 / 视频派单动作，都必须同步更新该账本；禁止只在对话上下文里记忆。

- `active_asset_pool` 记录当前允许参与下游的 ACTIVE 节点 / 路径 / asset_type / identity_token / prop_token / 所属 video_task_id。
- `deprecated_asset_pool` 记录被替换或失败隔离的旧节点 / 旧路径 / 废弃原因 / 替代资产。
- `question_authorization_log` 记录每次 question 授权范围、时间、动作名和是否全自动穿透。
- `external_skill_load_log` 记录每阶段实际加载的 Skill 名称、用途、输出注入位置和冻结点。
- `chain_freeze_manifest` 是全链路冻结总表，记录 A0/A1/A2/A3/A4/B1-B5/B6-B8 每个核心文档、结构化真值、派单载荷、资产登记、引用映射、外部 Skill 优化结果和最终提示词的冻结状态。每条记录至少包含：`freeze_id`、`stage`、`object_type`、`object_name_or_node`、`source_stage`、`upstream_freeze_ids`、`frozen_at`、`content_hash_or_length_snapshot`、`allowed_mutation_scope`、`mutation_owner`、`qc_status`。缺少冻结记录的对象不得进入下游。凡冻结对象会被某个 `video_task_id` 消费，必须同步把该 `freeze_id` 回填到对应 `video_task_mapping[video_task_id].stage_freeze_ids` 或 `dispatch_payload_freeze_ids`；全段通用对象必须回填到本段全部已创建的 `video_task_id` 空槽。禁止只写总表、不写任务映射索引。
- `core_doc_freeze_records` 记录 A0、A1、A2、空间真值调用中心、视频提示词列表等核心文本节点的冻结快照。冻结后只允许追加明确版本化的新小节或通过账本登记的修复补丁；不得原地覆盖、删改或摘要化旧真值。
- `dispatch_payload_freeze_records` 记录 A3/A4/B1-B5/B6-B8 每次图片、舞台定位图、黑白分镜、视频派单的 `[MANDATORY DISPATCH PAYLOAD]` 和最终 Verbatim 包装层快照。下游必须读取冻结版本，禁止重新口述或二次总结。
- `stage_qc_log` 记录每阶段 PASS / FAIL、FAIL 原因、修复动作和重试次数。任何回 A0、回 A1/A2、重绘 A4、重做 B1-B5、重编 B6/B8 或 QC 自动重跑动作，必须先写入本日志并同步递增 `fail_counter_by_stage[阶段名]`；禁止无账本记录的隐式回退，避免死链路与无限循环。
- `lineage_audit_chain` 记录 A0 -> A1 -> A2 -> A3 -> A4 -> B1-B5 -> B6-B8 的节点来源、reference image paths、派单 payload 摘要和产物路径。
- 每次进入 A4、B1-B5、B6-B8 前，必须执行 `Reference Validity & Lineage Continuity Preflight`，但预检上游范围必须按阶段裁剪，禁止要求尚未生成的下游对象存在，避免死链：A4 只验证 A0/A1/A2/A3 与空间真值；B1-B5 验证 A0/A1/A2/A3/A4；B6-B8 验证 A0/A1/A2/A3/A4/B1-B5。预检逐项验证当前 `video_task_id` 对应阶段范围内记录存在、状态为 ACTIVE、路径可解析、无孤儿路径、未被 `[DEPRECATED_OLD_VERSION]` 替换、A3 已冻结 `A3_SCOPE_MANIFEST` 且 `a3_completion_status: PASS`、A4/B1-B5/B6-B8 消费链中的 `source_a3_scope_manifest_freeze_id` 均指向同一个 PASS manifest、`a4_generated_after_a3_manifest: true`、`b1_b5_generated_after_a3_manifest: true`、`source_space_truth_node`、`source_space_truth_version`、`source_coordinate_camera_baseline_section`、`table_node_version` 与当前任务一致，且 `lineage_audit_chain` 在该阶段范围内没有断点。预检通过后必须把 `reference_validity_status: PASS` 与 `lineage_continuity_status: PASS` 回写到当前 `video_task_mapping[video_task_id]`；任一断点 / 版本错配 / 旧节点 / 坐标基准缺失触发 `[E06: Reference Resolve Failure]` 或 `[E05: Spatial Data Corruption]`，禁止继续下游。若预检发现“被要求检查的对象属于当前阶段尚未生成的下游产物”，该检查项本身判定为预检配置错误，必须修正阶段范围，不得循环等待。

## 链路接口契约 / Link Interface Contract

每个阶段在写入 A0 `[SSC_RUNTIME_LEDGER]` 时，必须同步声明本阶段的接口关系，禁止只产出内容、不说明上下游消费关系。每个 `video_task_id` 至少维护：

```text
upstream_producer_map:
  <field_name>:
    producer_stage: A0 | A1 | A2 | A3 | A4 | B1-B5 | B6 | B8
    producer_object: <节点名 / freeze_id / asset_id / payload_id>
    produced_status: pending | PASS | FAIL
    produced_at: <时间或 pending>
    empty_allowed: true | false
    if_empty_go_to: <回退阶段>

downstream_consumer_map:
  <field_name>:
    consumer_stage: A1 | A2 | A3 | A4 | B1-B5 | B6-B8 | QC
    consumer_object: <节点名 / payload_id>
    consume_mode: exact_copy | structured_transform | reference_path | qc_only
    must_not_wait_for: <尚未生成的未来阶段对象列表>

link_interface_audit_status: pending | PASS | FAIL
```

执行规则：

- 任一下游 consumer 字段必须能在 `upstream_producer_map` 找到明确 producer；找不到 producer，触发 `[E13: Link Interface Contract Failure]`。
- 任一 producer 字段必须至少有一个 consumer，或显式标注 `archive_only: true`；否则视为死链 / 孤儿数据，触发 `[E13: Link Interface Contract Failure]`。
- `pending`、`unknown`、`none`、空字符串、空数组 `[]`、空对象 `{}` 只能表示“尚未生产”，不得作为 PASS、不得被 B8 或 QC 当作有效输入；误判触发 `[E14: Empty Upstream Data / Pending-as-PASS Failure]`。
- 若 consumer 发现上游数据为空，必须回到该字段标注的 `if_empty_go_to` producer 阶段；禁止在 consumer 阶段反复重试、猜测补写或绕过接口。
- `must_not_wait_for` 用于防死链：A4 不得等待 B1-B5 / B6-B8；B1-B5 不得等待 B6/B8；B6-B8 不得等待尚未派发的视频输出。若某阶段检查项要求未来阶段对象存在，判定为接口配置错误，必须修正检查范围，不得循环等待。
- 任一接口失败修复前必须写入 `stage_qc_log` 并递增 `fail_counter_by_stage`。同一 `video_task_id`、同一字段、同一失败原因连续两次未修复，必须停止自动修复并通过高危 `question` 弹窗请求人工裁决。

## 真值与载荷

- A0 是所有下游母体数据中心；A1/A2/A3/A4/B1-B8 必须从 A0 或三核心文档抽取，不得凭对话历史散提。
- A0 新增的 `dialogue_intent_delivery_matrix`、`task_dialogue_inventory`、`video_output_format_lock`、`video_model_capability_risk_register`、`performance_substitution_plan`、`reference_requirements` 是全链路真值，不得停留在 A0 私有字段。A1 必须摘要继承，A2 必须转成 Panel / Temporal / 道具动作 / 参考需求载荷，A3/A4 必须消费静态替代道具、空间状态和参考需求接口，B1-B5 必须进入黑白分镜结构化文本负载与剪枝清单，B6-B8 必须转成 `dialogue_verbatim_diff_table`、`dialogue_delivery_mode_check`、`video_output_format_check`、`expected_video_reference_assets` 与 `model_capability_risk_execution_check`，QC 必须逐段验收。任一阶段缺消费记录，视为空链路，触发 `[E01: Missing Script/Assets]`、`[E13: Link Interface Contract Failure]` 或 `[E14: Empty Upstream Data / Pending-as-PASS Failure]`。
- `video_output_format_lock` 是最终视频模型、比例、时长、分辨率和声音开关的唯一真值源。默认 `final_video_aspect_ratio: 9:16`，只有用户明确授权才能覆盖；A3 视觉资产、A4 舞台定位图、B1-B5 黑白分镜、参考图物理尺寸或画布比例均不得反向污染最终视频比例。B8 `final_video_model_prompt_text`、`[FINAL_DISPATCH_PROMPT]`、`video_agent_verbatim_wrapper` 与实际 video agent 派发参数必须全部等于该锁；不一致触发 `[E10: Video Output Format Drift]`。
- `task_dialogue_inventory` 是当前 `video_task_id` 源对白全集锁。B6/B8 不得只保护 `dialogue_source_lock.required_dialogues`；凡属于当前视频任务且没有 `omission_authorization: user | script_explicit` 的源对白，都必须逐字进入 B6 `[Audio Hook]`、B8 `final_video_model_prompt_text` 与 video agent Verbatim 包装层，并通过 `dialogue_verbatim_diff_table` 三段 exact match；不一致触发 `[E11: Dialogue Verbatim Diff Failure]`。
- B1-B5 的参考图剪枝只在 `image2` 16 张上限被超过时触发；若 `@STAGE_MAP_VISUAL + 彩色资产` 总数小于或等于 16 张，必须全量传入当前任务必要参考图。B1-B5 剪枝不得作为 B8 视频参考图删减依据。B8 必须从 A0 `active_asset_pool`、当前 `video_task_id.reference_requirements`、A2 场景 / 角色 / 道具清单、B1-B5 被剪枝资产清单和当前 ACTIVE 黑白分镜反向建立 `expected_video_reference_assets`；最终派发给 video agent 的 `actual_video_agent_image_paths` 必须与冻结的 `final_reference_image_paths` 数量、顺序、路径完全一致。缺失应进入视频的 ACTIVE 参考资产或派发路径不一致，触发 `[E12: Video Reference Coverage Failure]`。
- 阶段内部派发、图片生成、舞台定位图和黑白分镜任务必须编译为 `[MANDATORY DISPATCH PAYLOAD]`，禁止自然语言散文式压缩。唯一例外是 B8 正式派发给视频模型前生成的最终提示词本体：它必须按“最终视频模型纯提示词模板最高铁律”编译为自然语言纯提示词，并写入 `final_video_model_prompt_text`，以 `model / ratio / duration / generate_audio` 开头，接 `生成N段连贯的剧情视频`、`参考图使用规则`、`镜头N（Xs）` 和整体风格收束；整体风格固定为 `超写实电影质感`，动态范围固定为 `Dynamic Range 15 stops`。这属于最终模型提示词格式编译，不等于压缩、删减或改写冻结剧情内容。`[FINAL_DISPATCH_PROMPT]` 是该本体的最高优先级命名冻结物，必须与 `final_video_model_prompt_text` 逐字一致。主 Agent 派发给 video agent 的外层 `task_description` 必须使用 `Verbatim prompt N (use as-is)` 包裹 `[FINAL_DISPATCH_PROMPT]` 全文以防二次改写，包装层不属于最终提示词本体；禁止以普通说明段落、摘要段落或“请根据以下内容生成”等形式传递。
- 全链路冻结保护覆盖所有用提示词或 task_description 生成 / 派单 / 整理出的对象，不只保护 B6/B8 视频提示词。A0 影视工业体系数据中心、A1 故事板概要、A2 场景调度表与空间真值、A3 视觉资产派单载荷、A4 舞台定位图 media_node / table_node 派单载荷、B1-B5 黑白分镜 task_description、B6 工作文档块和 B8 最终派发提示词，在阶段 QC 通过或用户授权确认后都必须冻结并写入 `chain_freeze_manifest`。冻结对象只能原样继承，不得修改、压缩、精简、提炼、缩减、概括、重写、截断、删减、合并同义句，且不得用“同上 / 已继承 / 按调度表”替代冻结字段。合法变更只限 `allowed_mutation_scope` 内声明的机器引用层：真实路径、canvas node id、版本号、`@IMAGE_ASSET_N` 重索引、废弃 / 替换状态、QC 补丁记录。凡需要改变冻结剧情、空间、坐标、台词、动作、表演、声音、资产决策或视频任务切分，必须新建版本化补丁记录，更新 freeze_id，旧对象进入 `[DEPRECATED_OLD_VERSION]` 或保留为历史快照，禁止原地覆盖。半自动和全自动两种模式都必须根据前序剧本剧情需要，在链路对应阶段加载用户自建外部 Skill 能力优化提示词；优化完成后的提示词、task_description、`视频提示词列表.md` 段落和所有 Block 立即冻结，只能原样传递。唯一例外是 B8 最终视频模型派发前的格式编译：只允许把冻结工作文档块转换为用户指定的自然语言纯提示词模板，并写入 `final_video_model_prompt_text`，不得改变冻结内容语义；若上游或外部 Skill 产出“真人实拍质感竖屏微短剧”等近似风格词，B8 必须统一覆盖为 `超写实电影质感`，凡涉及动态范围必须统一写为 `Dynamic Range 15 stops`。随后主 Agent 只能用 `Verbatim prompt N (use as-is)` 外层包装透传 `[FINAL_DISPATCH_PROMPT]` 给 video agent，包装块内部必须与 `final_video_model_prompt_text` / `[FINAL_DISPATCH_PROMPT]` 逐字一致；N 为同批视频任务序号，按 `1/2/3/4...` 顺序对应，不得跳号、乱序或复用序号。提示词文本长度本身不是限制条件，不得因为提示词长而拆分或改写。只有当单个 10-15 秒视频无法承载上级链路剧本要求表达的剧情、镜头、台词、动作、情绪、声音或转场时，才回到 `视频任务切分计划` 拆成更多 10-15 秒视频任务；若涉及 required dialogue，必须先查 `dialogue_intent_delivery_matrix`，未授权替代则拆分，已授权 interrupted / swallowed / performance_only 则保留授权与反证检查记录。
- **禁止借冻结偷懒 / No Freeze-Induced Compression Backdoor**：冻结对象被下游读取后，不等于下游可以只写“已冻结 / 已继承 / 见上游 / 按舞台定位图 / 参考黑白分镜 / 原样继承”。任何下游 consumer 都必须把本阶段会消费的强制字段完整展开到当前 `[MANDATORY DISPATCH PAYLOAD]`、task_description、`视频提示词列表.md` 工作块、`[Panel Execution Chain]`、`final_video_model_prompt_text` 或 Verbatim 包装层内。A4 → B1-B5 → B6-B8 必须逐级展开 100x100 坐标系、人物/道具形状颜色映射、`stage_position_xy`、`stage_position_xyz`、`facing_target_xy/xyz`、紫白色朝向箭头语义、`screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_position_xyz`、`camera_target_xyz`、`camera_direction_text`、`camera_screen_position_text`、`focal_length_mm`、`movement_path_xyz`、`movement_direction_text`、Eyeline、相对距离、Panel 1-9 行列位置、可见/离画/遮挡人物锁。任何只写概括句而未展开消费字段的阶段，即使上游已有冻结记录，也判定 `[E08: Chain Freeze Violation]` + `[E13: Link Interface Contract Failure]`，污染产物必须隔离并从最近 producer 阶段重做。
- `Segment Visual & Tone Lock`、`Segment Avoid`、`Scene Scheduling Sheet Truth Extract`、`Panel Character Spatial Matrix`、`Panel Spatial Lock` 不得删除、概括、隐藏或用“同上 / 已继承 / 按调度表”替代。
- `Character Count Lock / 人物数量锁` 是 A4、B1-B5、B6-B8 的强制真值接口。每个 `video_task_id` 必须建立并逐阶段继承：`allowed_visible_characters`、`allowed_visible_character_count`、`allowed_character_nodes`、`forbidden_extra_people`、`character_count_lock_status`。允许出现的人物只能来自锁定名单；场景参考图、评审棚 / 工作人员 / 人群语义、合并人物参考图或模型自身推断都不得扩展出未列名人物。未列名人物、人形剪影、群众、额外评委、额外工作人员、路人、游客、背景旁观者、匿名剪影或合并人物参考图被扩展为更多人物，均触发 `[E15: Character Count Lock Failure]`。
- `Character Count Lock / 人物数量锁` 必须写入 A4 table_node 顶层、A0 `video_task_mapping[video_task_id]`、B1-B5 每个 Panel 的 `visible_characters / offscreen_characters / occluded_characters`、B6 `[Panel Execution Chain].character_count_lock_payload`、B8 `final_video_model_prompt_text`、`[FINAL_DISPATCH_PROMPT]` 和 video agent `Verbatim prompt N (use as-is)` 包装层。B8 每个镜头必须自然语言写明本镜头只出现哪些已声明人物，禁止用“评委席 / 工作人员 / 人群 / 现场人员”等泛化词替代名单。
- 生成类成片图像默认禁止出现坐标 / 字段 / 多余文字，不代表 task_description 可以删除坐标字段；坐标是幕后空间锁。合法例外仅限：A4 舞台定位图中的坐标网格 / 中文角色全名标签 / 坐标指向文字，以及黑白 3x3 分镜中的 `Panel 1` 至 `Panel 9` 顺序文字。除这些阶段指定文字外，仍禁止任何额外文字。
- **中文角色全名保真锁**：凡用户剧本、A0、A1、A2、A4 table_node、B6/B8 中已有中文角色名，任何阶段都必须逐字使用中文角色全名，不得改写为中文短名、昵称、省略称、拼音首字母、英文缩写、英文代号、罗马字或 identity_token 片段。A4 舞台定位图的可见角色标签也必须使用中文角色全名；若画面空间不足，必须调整排版、字号、引线或图面留白来容纳全名，禁止用“赵 / 林 / 专家”这类中文短名或 `ZQM / LZX / EXP` 这类机器代号替代。正式叙事文档、提示词、对白、人物数量锁和视频最终提示词必须使用中文角色全名。道具、场景、地名、组织名等中文实体若已有完整中文名称，也不得改写为拼音首字母、英文缩写、英文代号、罗马字或非全名标签；机器字段中的 token 只可作为隐藏结构化字段使用，不得替代对用户可见或叙事可读的中文全名。

## 错误码

- `[E01: Missing Script/Assets]`：缺少上游真值或必要资产。
- `[E05: Spatial Data Corruption]`：空间字段、坐标、矩阵或摄影机坐标损坏。
- `[E06: Reference Resolve Failure]`：占位符、节点、路径、`image_paths` 或引用映射无法解析。
- `[E07: Required Reference Missing]`：阶段必须读取的 reference 缺失或未读取。
- `[E08: Chain Freeze Violation]`：`chain_freeze_manifest`、`core_doc_freeze_records` 或 `dispatch_payload_freeze_records` 缺失；冻结对象缺 `freeze_id` / `content_hash_or_length_snapshot` / `allowed_mutation_scope`；冻结后发生未授权改写、压缩、摘要、删减、同义改写、同上替代、hash / length snapshot 不匹配，或下游读取了未冻结 / 已废弃版本。触发后必须停止下游，写入 `stage_qc_log`，隔离污染产物，并回到最后一个冻结通过的 checkpoint 以版本化补丁修复。
- `[E09: Storyboard Model Parameter Drift]`：黑白 3x3 分镜 B1-B5 的派单载荷、冻结记录、QC 记录或实际生成 metadata 未显式满足 `model: gpt-image-2`、`model_alias: image2`、`resolution: 1k`、`quality: medium`、`aspect_ratio: 16:9`，或错误出现 / 继承 `resolution: 4k`、`quality: low`、`quality: high`、`画质：低`、`画质：高`、`low quality` 或 `high quality`。触发后必须停止进入 B5 PASS，隔离污染分镜产物，并用 `image2 / 1k / 16:9 / medium`（画质：中）重新派单。
- `[E10: Video Output Format Drift]`：B8 `final_video_model_prompt_text`、`[FINAL_DISPATCH_PROMPT]`、`video_agent_verbatim_wrapper` 或实际 video agent 派发参数中的 model / ratio / duration / generate_audio 与 A0 `video_output_format_lock` 不一致；未经用户明确授权把默认 `9:16` 改为 `16:9` 或其他比例；从 A3/A4/B1-B5 参考资产、舞台图、黑白分镜或参考图物理比例继承最终视频比例。触发后必须停止派发，回到 A0/B8 修正格式锁与最终提示词。
- `[E11: Dialogue Verbatim Diff Failure]`：A0 `task_dialogue_inventory` 中当前 `video_task_id` 未获 `omission_authorization: user | script_explicit` 的源对白，在 B6 `[Audio Hook]`、B8 `final_video_model_prompt_text` 或 video agent Verbatim 包装层中缺失、改字、换说话人、被概括、被旁白化、被沉默化或 exact match 失败。触发后必须停止派发，回到 A0 拆分任务或请求用户裁决。
- `[E12: Video Reference Coverage Failure]`：B8 `expected_video_reference_assets` 中应进入视频模型的 ACTIVE 场景 / 人物 / 道具 / 合并参考 / 当前黑白分镜 / 可选光影资产缺失；B1-B5 剪枝污染 B8 视频参考图；正式派发给 video agent 的 `actual_video_agent_image_paths` 与冻结的 `final_reference_image_paths` 数量、顺序或路径不一致；`@STORYBOARD_GRID` / 可选光影尾部锚点位置不正确。触发后必须停止派发并回到 B8 重建引用清单，必要时回 A3 或 B1-B5 补资产。
- `[E13: Link Interface Contract Failure]`：任一下游 consumer 字段找不到明确 producer；任一 producer 字段无 consumer 且未标注 `archive_only`；`video_task_mapping` 未预创建下游已引用字段；`reference_requirements` 缺失；`upstream_producer_map` / `downstream_consumer_map` / `link_interface_audit_status` 缺失；某阶段检查项要求尚未生成的未来阶段对象存在，造成死链等待。触发后必须停止当前 consumer 阶段，回到 producer 阶段补接口或修正检查范围。
- `[E14: Empty Upstream Data / Pending-as-PASS Failure]`：`pending`、`unknown`、`none`、空字符串、空数组 `[]`、空对象 `{}` 被当作 PASS 或有效输入；`reference_requirements.resolved_asset_ids == []` 却进入 B8；`actual_video_agent_image_paths` 仍为 pending 却通过派发前检查；任何空数据被下游自行猜测补写。触发后必须停止下游，按字段 `if_empty_go_to` 回到真实 producer 阶段，不得在 consumer 阶段循环重试。
- `[E15: Character Count Lock Failure]`：A4、B1-B5、B6-B8 任一阶段缺少人物数量锁字段；角色色块 / 火柴人 / 线框人偶 / 人形剪影数量超过 `allowed_visible_character_count` 或当前 Panel `visible_characters`；B8 `final_video_model_prompt_text`、`[FINAL_DISPATCH_PROMPT]`、video agent Verbatim 包装层缺少人物数量锁；出现未列名人物、额外评委、额外工作人员、游客、路人、群众、背景旁观者、匿名剪影，或合并人物参考图被误解为可扩展人群。触发后必须停止当前阶段，回到真实 producer 阶段补齐人数锁；若污染已生成图 / 视频，必须隔离污染产物并重做。
- `[E16: A3 Asset Completion Barrier Failure]`：A3 未建立或未冻结 `A3_SCOPE_MANIFEST`；`a3_completion_status != PASS`；仍存在 `pending_assets`、`failed_assets`、`deprecated_without_replacement`；未获用户明确授权却把段落完整资产范围缩小为单个 video_task_id 局部资产；下游仅凭局部 `coverage_status: PASS` / `resolved_asset_ids != []` 进入 A4；A4 / B1-B5 / B6-B8 任一阶段缺少 `source_a3_scope_manifest_freeze_id`；或 A4/B1-B5 产物早于有效 A3 manifest 却被继续消费。触发后必须立即停止 A4/B1/B6/B8，隔离已经提前生成的下游污染产物，回到 A3 补齐并冻结完整美术资产参考图范围；补齐后必须重做所有早于有效 manifest 的 A4 与 B1-B5。

## E08 修复协议

`[E08: Chain Freeze Violation]` 不得触发盲目重跑或无限回退。修复时必须先判定冻结违规类型：

1. **记录缺失但对象内容未变**：若对应对象仍是当前 ACTIVE 版本，且内容与上游真值一致，只允许补建冻结记录、补写 `freeze_id`、`content_hash_or_length_snapshot`、`allowed_mutation_scope` 和 `upstream_freeze_ids`；不得重写对象正文。
2. **对象内容已被污染或 hash / length snapshot 不一致**：必须从最近一个通过冻结的上游 `freeze_id` 新建版本化补丁或重做当前阶段产物；旧对象标记 `[DEPRECATED_OLD_VERSION]`，新对象生成新 `freeze_id`。
3. **不存在任何上游冻结 checkpoint**：不得继续下游，也不得反复重跑当前阶段；必须回到最早应生成冻结记录的阶段（通常 A0），创建首个冻结记录后再顺序推进。
4. **连续两次同一 E08 原因未修复**：停止自动修复，通过高危 `question` 弹窗暴露缺失的 `freeze_id`、对象名、阶段名、上游依赖和建议回退点，等待人工裁决。

E08 修复只能修冻结账本和版本链路，不得借修复名义改写剧情、台词、空间、动作、表演、声音或资产决策。
