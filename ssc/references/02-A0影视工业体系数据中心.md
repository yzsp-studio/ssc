## 视频任务参考需求接口 / Reference Requirements Interface

A0 必须为每个 `video_task_id` 预创建 `reference_requirements`，作为 A3、A4、B1-B5、B8 之间的参考图生产 / 消费接口。该字段不是 B8 临时推断结果，而是 A0 根据剧本、A1/A2 空间真值和资产决策生成的上游需求清单。最低结构：

```text
reference_requirements:
  video_task_id: <当前任务编号>
  required_scene_asset_ids: []
  required_character_identity_tokens: []
  required_prop_tokens: []
  required_lighting_reference: none | optional | required
  required_storyboard_grid: true
  forbidden_video_inputs: [stage_map]
  resolved_asset_ids: []
  missing_asset_requirements: []
  coverage_status: pending | PASS | FAIL
  a3_scope_manifest_ref: <A3_SCOPE_MANIFEST freeze_id 或 pending>
  a3_scope_mode: segment_full | task_only_explicit | pending
  a3_completion_status: PASS | FAIL | pending
  source_a3_scope_manifest_freeze_id: <freeze_id 或 pending>
  a4_generated_after_a3_manifest: true | false | pending
  b1_b5_generated_after_a3_manifest: true | false | pending
  producer_stage: A0/A2/A3/B1-B5
  consumer_stage: A4/B1-B5/B6-B8
```

执行规则：

- A0 负责创建需求空槽；A2 负责把当前任务角色、场景、道具和空间调度需求回填进 `required_*`；A3 负责把已生成的 ACTIVE 场景 / 人物 / 道具 / 光影资产回填到 `resolved_asset_ids`；B1-B5 负责把当前 ACTIVE 黑白分镜和 `pruned_asset_text_payload_manifest` 回填为 B8 可消费接口；B8 只能消费这些已生产接口，不得自行凭自然语言猜测缺失参考图。
- `reference_requirements.coverage_status` 为 `pending`、`FAIL`、`missing_asset_requirements != []`、`resolved_asset_ids == []`，或 `a3_scope_manifest_ref` / `source_a3_scope_manifest_freeze_id` 为空，或 `a3_completion_status != PASS`，或 `a4_generated_after_a3_manifest != true` / `b1_b5_generated_after_a3_manifest != true` 时，禁止 A4/B1-B5/B8 把该任务判定为可派发；必须回到对应 producer 阶段补齐。若 B8 发现接口为空仍尝试重建引用清单，触发 `[E16: A3 Asset Completion Barrier Failure]`、`[E13: Link Interface Contract Failure]` 或 `[E14: Empty Upstream Data / Pending-as-PASS Failure]`。
- 舞台定位图只允许作为 A4/B1-B5 的空间生产物与黑白分镜参考，不得进入最终视频 `image_paths`；若 `reference_requirements` 或 B8 `expected_video_reference_assets` 把 stage_map 列入视频输入，触发 `[E12: Video Reference Coverage Failure]` 或 `[E13: Link Interface Contract Failure]`。

## 对白保真锁 / Dialogue Preservation Lock

A0 创建或更新时必须从原始剧本逐句抽取对白，并写入 `dialogue_source_lock`。该字段是 A1/A2/A3/A4/B6/B8 的不可降级真值源，优先级高于“台词少而准”“留给表演时间”“沉默反应”等导演层建议。

`dialogue_source_lock` 至少包含：

```text
{
  required_dialogues: [
    {
      dialogue_id: <稳定编号，如 EP01-S01-D001>,
      speaker: <角色名>,
      text: <原始剧本文字，逐字保留>,
      source_line: <源文件行号或源段落>,
      source_scene: <场次 / 段落>,
      assigned_video_task_id: <承载该句的 10-15 秒任务>,
      required: true,
      preservation_rule: verbatim_no_delete_no_summarize_no_silent_reaction
    }
  ],
  optional_dialogues: [
    {
      dialogue_id: <稳定编号>,
      speaker: <角色名>,
      text: <原始剧本文字>,
      source_line: <源文件行号或源段落>,
      assigned_video_task_id: <任务编号或 pending>,
      required: false,
      optional_reason: <重复 / 可由动作表达 / 用户明确允许弱化>
    }
  ],
  over_capacity_resolution: split_video_task_not_dialogue_compression
}
```

执行规则：

- `required_dialogues` 必须逐字保留到 B6 `[Audio Hook]` 和 B8 `final_video_model_prompt_text` 对应镜头；不得删减、概括、换说话人或改写为旁白。唯一例外是同一 dialogue_id 在 A0 `dialogue_intent_delivery_matrix` 中已被 `decision_owner: user | script_explicit` 明确授权为 `interrupted / unfinished / swallowed / silent_due_to_script / performance_only`，且替代表演反证检查通过；否则不得改写为沉默 / 吸气 / 眼神 / 表情反应。`A0_analysis` 只能提出 `performance_replaceable_candidate` 或拆分建议，不能作为最终省略、片段化、沉默化或 performance_only 授权来源。
- “台词少而准”只允许处理 `optional_dialogues` 中明确标记为非必要的重复废话；不得作用于 `required_dialogues`。
- 若某个 10-15 秒任务无法同时承载 required dialogue、剧情、动作、表演、镜头和声音，必须在 A0 修改 `视频任务切分计划`，把该任务拆成多个 10-15 秒任务，并重新分配 `assigned_video_task_id`；禁止压缩对白来适配时长。
- A1/A2 回读校准时，如果发现 required dialogue 没有时间锚点，或在未获得 `dialogue_intent_delivery_matrix` 授权时被动作化为沉默反应，必须回写 A0 并重新切分任务，不能继续进入 B6。若已授权为非完整说出口交付方式，A1/A2 必须记录对应 `delivery_mode`、授权来源和反证检查结果。

## 对白意图与交付方式判定矩阵

A0 不得只把对白粗暴分为“保留 / 删除”。每句对白必须生成 `dialogue_intent_delivery_matrix`，用于说明这句台词为什么必须说、是否可由表演替代、谁拥有修改权限。B6/B8 只能继承该矩阵，不得临时凭“电影感”“节奏更好”自行改判。

每句对白至少包含：

```text
dialogue_intent_delivery_matrix:
  dialogue_id: <稳定编号>
  speaker: <角色名>
  original_text: <原始剧本文字>
  dialogue_function: [plot_information | conflict_turning_point | character_value | relationship_power | theme_expression | action_trigger | emotional_repetition | hesitation | atmosphere]
  audience_dependency: high | medium | low
  plot_dependency: high | medium | low
  relationship_dependency: high | medium | low
  theme_dependency: high | medium | low
  can_visual_replace: true | false
  can_performance_replace: true | false
  can_interrupt: true | false
  preservation_level: verbatim_spoken | authorized_fragment | performance_replaceable_candidate | optional
  delivery_mode: spoken | delayed_spoken | interrupted | unfinished | swallowed | silent_due_to_script | performance_only
  decision_owner: user | script_explicit | A0_analysis_suggestion
  final_omission_authorization_owner: none | user | script_explicit
  decision_reason: <结构化理由>
  qc_risk_if_removed: <信息丢失 / 关系变弱 / 情绪含糊 / 因果断裂 / 主题变弱 / 无>
```

判定标准：

- 凡提供新剧情信息、改变人物关系、触发后续动作、暴露人物价值观、形成冲突爆点、呼应主题、支撑因果转折或观众不听到就会误解剧情的台词，默认 `preservation_level: verbatim_spoken` 或 `authorized_fragment`。
- 凡只是重复已明确表达过的情绪、迟疑语气、口头填充、可由画面 / 动作 / 道具明确等价表达且不会损失信息的台词，A0 只能标记为 `performance_replaceable_candidate` 或 `optional` 候选；若该台词来自当前任务源对白且未获用户 / 剧本显式授权，仍必须默认进入 `task_dialogue_inventory` 并逐字交付。
- 剧本明确写“打断、说不出口、吞回去、沉默、张嘴却没说”时，`decision_owner: script_explicit`，可设置 `delivery_mode: interrupted / unfinished / swallowed / silent_due_to_script`，并写入 `final_omission_authorization_owner: script_explicit`。
- 用户明确指定时，`decision_owner: user`，优先级最高，可写入 `final_omission_authorization_owner: user`。
- `A0_analysis_suggestion` 不是授权来源，只能记录分析建议、替代候选或拆分建议；不得把 `final_omission_authorization_owner` 写成 A0_analysis，不得最终授权 omission / authorized_fragment / interrupted / unfinished / swallowed / silent_due_to_script / performance_only。
- 剧本没有说明且 A0 无法确定时，默认保守：先保留为 spoken；若影响节奏，回到 A0 拆分任务或用 `question` 让用户裁决，不得交给 B6/B8 临时删改。

替代表演反证检查：任何 `performance_replaceable_candidate` 都必须通过 5 项反证：信息不丢失、关系不变弱、情绪不含糊、节奏确实更好、后续因果仍成立。通过反证只代表“可向用户或剧本显式依据申请替代”，不等于已授权省略；任一不通过，必须恢复为 `verbatim_spoken` 或拆分视频任务。

## 视频模型能力边界预判 / Capability Risk Register

A0 读剧本时必须预判 AI 视频模型高风险动作，写入 `video_model_capability_risk_register`。该表的目的不是降低剧情表达，而是在进入分镜前把“模型容易做坏的精细动作”转译成更稳的电影化表现。

高风险动作包括但不限于：

- 精细书写 / 画符号 / 在纸上准确画叉 / 写字 / 签名 / 填表 / 手机打字。
- 复杂手部与小物互动：拧瓶盖、系扣、点火、夹取细小物、折纸、穿针、精确按键。
- 需要画面准确可读的文字、数字、图案、地图、UI、票据、印章、屏幕内容。
- 连续物理变化：纸张被准确撕成指定形状、液体精确泼洒轨迹、物体碎裂成指定图案。
- 多人交叉动作、遮挡下的手部动作、快速抢夺并改变道具状态。

每个风险动作至少记录：

```text
video_model_capability_risk_register:
  risk_id: <稳定编号>
  source_action: <原剧本动作>
  source_line: <源位置>
  risk_type: fine_hand_action | readable_text_symbol | small_prop_interaction | complex_physics | multi_actor_occlusion | continuity_sensitive_prop_state
  risk_level: high | medium | low
  narrative_function: <这个动作在剧情中承担什么功能>
  must_preserve_function: true | false
  literal_execution_allowed: true | false
  substitution_required: true | false
  substitution_strategy: <见下方替代表现策略>
  substitution_reason: <为什么这样更稳且不损剧情>
```

替代表现策略：

- **结果先行**：不拍“画叉过程”，改拍已经被红叉划掉的方案纸 + 角色手离开纸面 + 对方反应。
- **动作遮挡**：拍手臂落下、笔尖压住纸面的起势，不要求模型准确生成叉形轨迹。
- **声音替代**：用笔尖重重划过纸面的摩擦声、纸张被压住的闷响来表达动作完成。
- **反应替代**：拍被否定者眼神、呼吸、手指压纸，比拍精确画叉更稳定。
- **静态道具替代**：提前把“已画叉纸张 / 已盖章文件 / 已破损道具”做成道具参考图或关键帧，不让视频模型实时生成精确细节。
- **镜头切分**：将高风险精细动作拆成“起势 -> 结果 -> 反应”三个镜头，避免一镜到底强迫模型完成精确物理动作。

A0 必须输出 `performance_substitution_plan`，把高风险动作改写为不损剧情功能的镜头表达方案。若动作承担关键剧情功能，必须保留“功能”，可以替换“字面动作过程”；例如“画叉否定方案”的功能是权力宣判和方案被废，不一定必须实时拍清完整画叉过程。

## 视频任务切分计划

A0 必须输出 `视频任务切分计划`，根据剧情推进、镜头语言、表演细节、FACS/AU、身体语言、台词速度、无台词呼吸 / 环境声、空镜纯表演、物理动作、剪辑节奏与观众认知成本，计算应拆成多少个 10-15 秒视频任务；不得按集数机械分段。

每个 10-15 秒任务必须包含：

- 唯一任务编号，如 `EP1-01`、`EP1-02`。
- 剧情目标、起止状态、镜头功能、表演重点、声音重点、参考图需求、`required_dialogues_for_task`、`dialogue_source_lock_ids`、`dialogue_intent_delivery_matrix_ref`、`model_capability_risk_ids`、`performance_substitution_plan_ref`、`scene_cinematography_profile_ref`。
- `SSC Narrative Capacity Engine` 预算表：Event、Time、Cognitive、Performance、Causal、Information Delta、State Change、Genre Profile。
- 能力边界执行摘要：本任务是否包含高风险精细动作、是否需要替代表现、替代表现由哪个 Panel / 镜头 / 声音锚点承载。
- 时间预算：视觉阅读时间、定场时间、情绪停顿、声音先入、动作打点、落版时间。
- 一一映射：`任务编号 -> 舞台定位图 -> 黑白 3x3 分镜图 -> 视频提示词段`。

黑白 3x3 的 9 个 Panel 只是单个 10-15 秒任务内部的 9 个叙事 / 镜头子帧，不等于一集或一个段落只能生成 9 个视频任务。若 `视频任务切分计划` 产生 10 个任务，必须生成 10 套舞台定位图、10 张黑白 3x3 分镜图、10 个视频提示词段。禁止 `EP1-09`、`EP1-10` 等任务继续引用第一张黑白分镜图的 Panel 8 / Panel 9。

## SSC Narrative Capacity Engine

A0 必须用以下 8 项核心预算决定每个 10-15 秒视频任务是否能承载当前剧情，不得用提示词文本长度作为拆分依据。预算分两段执行：A0 首次创建时允许根据剧本 / 制作计划做初算；A1 故事板概要、A2 场景调度表和 `空间真值调用中心` 生成后，必须回读这些 MD / table_node 数据重新校准预算与 `视频任务切分计划`。最终是否拆分，以 MD 回读校准后的结果为准，不以 A0 初算为准。

1. **Event Budget / 事件预算**：统计本任务实际发生的叙事 Beat。最佳 1-3 个 Beat；4 个进入危险区，必须检查其它预算；5 个及以上强制拆分。发现秘密、争吵、抢夺、反转、逃跑等只要改变目标、风险、关系或信息状态，均算独立事件。
2. **Time Budget / 时间预算**：类型驱动，不用单一固定秒数。必须先确定 `Genre Profile`，再估算定场、动作、台词、表演、声音、转场、落点各自占用的 10-15 秒内部时间。短剧、电影、纪录片、广告、MV 的节奏参数不同，不得用同一秒数模板误杀快节奏剧情。
3. **Cognitive Budget / 认知预算**：输出 `Information Load`，统计观众在本任务内需要理解的新角色、新地点、新秘密、新关系、新设定、新目标或新规则。认知负荷高于当前类型可承载范围时拆分。
4. **Performance Budget / 表演预算**：输出 `Emotion Transition Count`。10-15 秒内建议不超过 2 次核心情绪转折；怀疑 -> 震惊 -> 崩溃这类多段心理变化必须给表演时间，不能被压成瞬间完成。
5. **Causal Depth / 因果深度预算**：统计因果链层数。10-15 秒内建议不超过 3 层；如 A 偷钥匙 -> B 发现 -> 误会 C -> C 被赶走 -> D 获利，虽然可写成一句话，但应拆分。
6. **Information Delta / 信息增量预算**：每个视频任务必须回答“观众获得了什么新信息”。最佳 1-3 个核心信息；0 个核心信息应删除或合并；5 个以上强制拆分。
7. **State Change / 状态变化预算**：统计人物、道具、空间、关系或剧情状态变化。单视频 1-3 项最佳；人物死亡、门打开、钥匙丢失、关系破裂、身份暴露等都必须登记为状态变化，并写入下游故事板 / 调度表 / 分镜 / 视频提示词继承链。
8. **Genre Profile / 类型配置文件**：作为所有预算的调速器。必须标明短剧、悬疑、纪录片、广告、MV、电影等类型及节奏倾向；所有 Event、Time、Cognitive、Performance、Causal、Information Delta、State Change 阈值都受 Genre Profile 调整。

若任一核心预算超载，优先回到 `视频任务切分计划` 拆分视频任务，而不是压缩提示词。若超载因素包含 `dialogue_source_lock.required_dialogues`，必须拆分任务并重新分配 `assigned_video_task_id`，不得删台词、缩台词或把对白改成沉默反应。

若超载因素包含 `video_model_capability_risk_register` 中的高风险精细动作，优先执行 `performance_substitution_plan` 或拆分镜头 / 拆分视频任务，不得把“准确实时书写、画叉、读清 UI、复杂手部小物互动”等字面动作硬塞给视频模型。能力边界风险不是删剧情理由；必须保留 `narrative_function`，只替换更稳定的画面交付方式。

## MD 回读校准

A1/A2 完成后必须执行 `Narrative Capacity Recalibration`：重新读取 `故事板概要 — [集数][段落编号][场景名]`、`场景调度表 — [集数][段落编号][场景名]` 和 `空间真值调用中心 — [集数][段落编号][场景名]`，校准 A0 的 `SSC Narrative Capacity Engine` 与 `视频任务切分计划`。A4 舞台定位图 table_node 生成或修正后，如坐标、朝向、Z-index、视线、相对距离或运动路径改变，必须作为二次回读源重新执行本校准。

校准来源：

- Event Budget：从 A1 剧情范围、9 格动作概要、A2 Panel 动作关键帧列表回读。
- Time Budget：从 A0 Genre Profile、A2 `[Temporal_Anchor]`、台词 / 声音 / 动作打点回读。
- Cognitive Budget / Information Load：从 A1 人物 / 场景 / 道具信息提取表、A2 新关系 / 新目标 / 新空间结构回读。
- Performance Budget / Emotion Transition Count：从 A1 情绪目标、动作节拍、A2 Character State Machine 与 `key_action_timestamps` 回读。
- Causal Depth：从 A1 剧情范围、结尾衔接、A2 Blocking Logic 与 Focus Target 回读。
- Information Delta：从 A1 本段剧情范围、A2 Panel 动作关键帧和视频提示词继承规则回读。
- State Change：从 A1 起止状态、A2 角色站位表、道具坐标表、空间真值状态字段回读。
- Dialogue Delivery：从 A1 情绪目标、A2 `[Temporal_Anchor]` 和 `dialogue_intent_delivery_matrix` 回读，检查 required dialogue 是否仍按授权交付方式承载。
- Capability Risk：从 A1 9 格动作概要、A2 Panel 动作关键帧、道具坐标表和 `performance_substitution_plan` 回读，检查高风险动作是否已被替代表现执行；若 A1/A2 新增未经登记的高风险精细动作，必须回写 A0。
- Genre Profile：从 A0 类型配置保留，但可被 A1/A2 显示出的实际叙事节奏校准。

若回读后预算与 A0 初算不一致，必须 `hub_edit` 回写 `影视工业体系数据中心 — [集数][段落编号][场景名]`，更新 `视频任务切分计划`。若预算与初算一致，也必须在 A0 中记录 `Narrative Capacity Recalibration: completed` 并清除 `Narrative Capacity Recalibration Pending`。若因此新增或拆分视频任务，必须重新生成对应任务的舞台定位图、黑白 3x3 分镜图和独立提示词段。

## 辅助复杂度检查

以下 5 项只作为辅助检查，用于提醒 AI 视频稳定性风险，不得替代 8 项核心预算，也不得扩展成复杂数学模型。

1. **Consistency Load / 一致性检查**：简单标记低 / 中 / 高。关注服装、发型、伤口、道具状态、血迹、污渍、空间损坏等跨镜一致性风险；高风险时优先拆分或强化资产引用。
2. **Multi-character Interaction / 多角色交互检查**：按简单 / 中等 / 复杂判断。角色越多，视线、站位、遮挡、动作因果越容易崩；多人冲突、多人走位和多人视线交叉时优先拆分或强化舞台定位图 table_node。
3. **Prop Load / 道具检查**：关键道具建议不超过 3 个。若超过 3 个且都参与动作或因果变化，优先拆分或合并叙事功能；非关键道具只作为环境信息。
4. **Spatial Topology / 空间拓扑检查**：仅分简单 / 中等 / 复杂。打斗、追逐、多人戏、楼梯 / 多层空间、门窗进出、遮挡关系复杂时，必须强化空间真值和舞台定位图，不得靠自然语言描述硬塞。
5. **Model Capability Risk / 视频模型能力边界检查**：按低 / 中 / 高标记精细书写、准确符号、可读 UI、复杂手部小物互动、连续物理变化和多人遮挡动作风险。高风险时必须优先替代表现或拆镜头；禁止把能力边界风险伪装成删剧情、删台词或弱化冲突的理由。

## 不固化为铁律的导演层项目

镜头语法预算、视觉钩子预算和景别预算不得作为 SSC 系统级硬预算。它们属于类型模板或导演审美层：纪录片、广告、电影、MV、短剧的镜头语法和视觉钩子需求不同。SSC 只把它们作为 `Genre Profile` 下的可选调味，不得用来强制拆分或判定 FAIL。

## 类型驱动时间预算规则

1. 视觉信息阅读时间：复杂构图、群像、道具关系、手机 UI 或高信息画面必须预留理解时间；新场景必须有建立空间感的定场镜头。
2. 情绪停顿 / 余韵：震惊、感动、死亡、反转、悬念揭晓后必须预留 0.5-1 秒空气感或反应镜头。
3. 声音空间：新场景音景可先行或并行建立 1-2 秒；静默必须被当成叙事事件规划时长；关键音效打击点必须与动作过程匹配。
4. 剪辑物理：动接动必须预留运动启动、持续、停止和动量匹配时间；特效必须有出现、展示、消失时间；叠化、淡入淡出等转场须扣除首尾约 0.5 秒有效时长损耗。
5. 品牌 / 信息落版：商业短片 Logo / KV / 产品 / 购买按钮等关键信息必须有不少于 1.5-2 秒清晰静止展示；非商业叙事转化为情绪收束或信息记忆点。

15 秒默认参考模型仅作为初始估算：0-3 秒建立与铺垫，3-8 秒冲突或动作发展，8-12 秒反转或情绪顶点，12-15 秒落版、退场或情绪余韵。实际分配必须由 `Genre Profile` 调整：短剧可压缩建立并强化冲突钩子；纪录片可增加解释 / 观察时间；广告可保留产品 / 品牌落点；MV 可让音乐节拍优先于对白信息。不得把该默认模型当作所有类型的固定秒数铁律。

## Seedance 标准模板字段

A0 必须内置：`model: Seedance 2.0`、`resolution: 480P`、`aspect_ratio: 9:16`、`duration: 15s`、`generate_audio: on`、Reference roles、Medium、Sound、Primary performance emphasis、分秒时间码、Negative / restrictions。

## 最终视频输出格式锁 / Video Output Format Lock

A0 必须为每个 `video_task_id` 建立 `video_output_format_lock`，作为 B6/B8 和正式 video agent 派发的唯一视频输出格式真值源。字段至少包含：

```text
video_output_format_lock:
  video_task_id: <当前任务编号>
  final_video_model: seedance2.0 | <用户明确指定模型>
  final_video_aspect_ratio: 9:16
  final_video_duration: 15s
  final_video_resolution: 480P | <用户明确指定分辨率>
  generate_audio: on
  source_of_truth: A0.Seedance_standard_template_fields | user_explicit_override
  user_override_record: <若用户明确改比例 / 模型 / 时长 / 声音，记录 question 或原话来源；否则 none>
  must_not_inherit_from:
    - A3 visual asset aspect_ratio
    - A4 stage map aspect_ratio
    - B1-B5 storyboard_grid aspect_ratio
    - reference image physical aspect_ratio
```

执行规则：

- `final_video_aspect_ratio` 默认继承 A0 Seedance 标准模板字段 `aspect_ratio: 9:16`。只有用户通过 `question` 或原话明确指定横屏 / 16:9 / 其他比例时，才允许改写，并必须记录 `user_override_record`。
- A3 人物 / 场景 / 道具 / 光影参考图的 `16:9`，A4 舞台定位图画布比例，B1-B5 黑白 3x3 分镜 `16:9`，都只是前期资产 / 参考图 / 分镜板画布比例，不是最终视频成片比例。B6/B8 和 video agent 派发禁止从这些参考资产物理比例反推或继承最终视频比例。
- B8 `final_video_model_prompt_text`、`[FINAL_DISPATCH_PROMPT]`、`video_agent_verbatim_wrapper` 和实际 video agent `ratio` 参数必须逐项等于 `video_output_format_lock.final_video_aspect_ratio`。不一致触发 `[E10: Video Output Format Drift]`，禁止派发或必须隔离错误派发记录。

## 当前任务对白全集锁 / Task Dialogue Inventory Lock

A0 必须为每个 `video_task_id` 建立 `task_dialogue_inventory`。当前任务剧情范围内的全部源对白默认视为 required，除非剧本原文或用户明确授权 omission / interrupted / swallowed / performance_only。字段至少包含：

```text
task_dialogue_inventory:
  video_task_id: <当前任务编号>
  all_source_dialogues_in_task:
    - dialogue_id: <稳定编号>
      speaker: <角色名>
      text: <原始剧本文字，逐字保留>
      source_line: <源文件行号或源段落>
      assigned_video_task_id: <当前任务编号>
      required_by_default: true
      allowed_to_omit: false
      omission_authorization: none | user | script_explicit
      authorization_source: none | user | script_explicit
      delivery_mode: spoken | delayed_spoken | interrupted | unfinished | swallowed | silent_due_to_script | performance_only
  pass_condition: all dialogue rows either appear verbatim in B6/B8/video wrapper or have explicit omission_authorization
```

执行规则：

- `dialogue_source_lock.required_dialogues` 不得成为唯一保护范围；当前 `video_task_id` 剧情范围内所有源对白必须先进入 `task_dialogue_inventory`，再由 `dialogue_intent_delivery_matrix` 判定交付方式。
- 未被 `user` 或 `script_explicit` 明确授权省略的对白，默认必须逐字进入 B6 `[Audio Hook]`、B8 `final_video_model_prompt_text` 和 `video_agent_verbatim_wrapper`。
- `A0_analysis_suggestion`、导演建议、节奏建议、B1-B5 摘要或旧补丁不得把 `omission_authorization` / `authorization_source` 改成授权态；若出现 A0_analysis 作为最终授权来源，A0 QC 直接 FAIL。
