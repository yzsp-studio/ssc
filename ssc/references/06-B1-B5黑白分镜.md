# B1-B5 黑白 3x3 分镜

本文件由 `00-强制读取索引.md` 强制触发。进入 B1-B5 任一动作前必须读取本文件；未读取即触发 `[E07: Required Reference Missing]`。

## B1 输入继承

进入 STEP B 前必须重新读取：

- `故事板概要 — [集数][段落编号][场景名]`
- `场景调度表 — [集数][段落编号][场景名]`
- `空间真值调用中心 — [集数][段落编号][场景名]`
- 当前任务对应的舞台定位图 media_node / table_node
- 全部允许范围内视觉资产节点 / 路径，以及 B1.2 计算后的真实 `image_paths` 资产清单；只有总参考图数超过 16 张时，才记录被剪枝资产清单

黑白分镜必须把当前分镜生图任务所绑定 `video_task_id` 的唯一舞台定位图 media_node 与全部必要场景 / 人物 / 关键道具 / 合并参考图作为真实 `image_paths` 传入。只有 `@STAGE_MAP_VISUAL + 彩色资产` 总数超过 16 张时，才允许按 B1.2 剪枝；被剪枝资产不得丢失，必须以结构化文本写入 task_description，并保留 `identity_token` / `prop_token`、原始 `asset_image_path`、剪枝原因和完整空间字段。禁止只写自然语言资产描述。不得只读取舞台定位图视觉节点；table_node 与空间真值文档是几何真值。

进入黑白分镜前必须比对 table_node 的版本号 / 时间戳 / 坐标字段 / `_text` 方位字段与空间真值文档核心字段是否一致，并且必须逐项读取 `空间真值调用中心` 的 `坐标与摄影机基准` 小节。不一致时回退至 A4 重绘空间真值表格。舞台定位图 media_node 只作为视觉 blocking 参考；每个 Panel 的数值坐标、朝向、摄影机和自然语言方位描述必须以同一 `video_task_id` 的 `空间真值调用中心.坐标与摄影机基准` + A4 table_node 为唯一真值源。若坐标字段为裸数字或无键数组，必须先回退 A2/A4 标准化为 X/Y/Z 对象，禁止进入黑白分镜生图。

**B1 入口 A3 完整性继承锁**：进入 B1-B5 前必须读取并记录已冻结的 `A3_SCOPE_MANIFEST`，验证 `completion_check.a3_completion_status: PASS`、`pending_assets: []`、`failed_assets: []`、`deprecated_without_replacement: []`，并确认当前 A4 舞台定位图的 `source_a3_scope_manifest_freeze_id` 等于该 PASS 版本的 freeze_id，且 A4 `generated_at` / `freeze_id` 晚于该 A3 manifest。若 A4 是在有效 A3 manifest 之前生成，或只记录局部 `coverage_status: PASS` / `resolved_asset_ids != []` 而没有完整 A3 manifest，必须触发 `[E16: A3 Asset Completion Barrier Failure]`，将该 A4 标记为提前生成污染产物，禁止进入 B1-B5，必须回 A3 补齐 manifest 后重做 A4。

## B1.2 分镜生图通道限流

底层分镜生图底座 `image2` 参考图上限为 16 张。`@STAGE_MAP_VISUAL` 固定占用 `image_paths[0]`，因此彩色资产最多可保留 15 张。若当前 `video_task_id` 的舞台定位图 + 全部必要场景 / 人物 / 关键道具 / 合并参考图总数小于或等于 16 张，禁止剪枝，必须全量传入真实 `image_paths`。只有候选参考图总数超过 16 张时，才允许执行分镜前置资产剪枝：

- `@STAGE_MAP_VISUAL` 永远保留为 `image_paths[0]`，不得被剪枝。
- 彩色资产槽位固定为 `image_paths[1..15]`，总数不得超过 15 张。
- 优先保留当前任务唯一场景参考图、全部核心出场角色参考图、角色合并参考图、正在被操作 / 移动 / 递交 / 争夺 / 遮挡空间关系的关键道具参考图和道具合并参考图。
- 正在被操作、移动、递交、争夺或遮挡空间关系的关键道具必须优先于非行动背景角色保留；若该道具是 A0 `performance_substitution_plan` 的静态结果道具（如已画叉纸张），优先级高于普通背景角色和非行动场景细节。如保留关键道具会使彩色资产超过 15 张，必须按叙事权重在“可合并替代资产 / 次要背景角色 / 非手持道具 / 非必要光影图”中继续剪枝，直到满足 16 张总上限。
- 其余背景角色、非操作道具、被剪枝场景、光影图转为结构化文本写入 [Pruned Asset Text Payload]，但必须保留其 `identity_token` / `prop_token`、原始 `asset_image_path`、剪枝原因和空间字段。

禁止超过 16 张裸流参考图；若 `@STAGE_MAP_VISUAL + 彩色资产` 仍超过 16 张，判定 `[E06: Reference Resolve Failure]`，不得调用 image agent。若总数小于或等于 16 张却未全量传入必要参考图，同样判定 `[E06: Reference Resolve Failure]`。

**B1-B5 参考图数量硬锁 / Storyboard Reference Count Lock**：B1-B5 派单前必须建立 `expected_storyboard_reference_image_paths`，公式固定为：`@STAGE_MAP_VISUAL` 1 张 + 当前任务必要场景参考图 + 当前任务全部允许可见人物参考图 / 必要合并人物参考图 + 当前任务全部关键道具参考图 / 必要合并道具参考图 + 可选光影图（若 A0/A3 判定当前任务需要）。必须同步写入 `[MANDATORY DISPATCH PAYLOAD]`、`Reference Mention Map`、A0 `video_task_mapping[video_task_id]`：`expected_storyboard_reference_count`、`actual_storyboard_reference_count`、`storyboard_reference_exact_match_check.same_count / same_order / same_paths`、`pruning_allowed`、`pruned_asset_text_payload_manifest`。只有 `expected_storyboard_reference_count > 16` 时，`pruning_allowed` 才能为 true；若 `expected_storyboard_reference_count <= 16`，`actual_storyboard_reference_image_paths` 必须与 expected 数量、顺序、路径逐项一致，不得剪枝、不得额外加入非当前任务资产、不得只写自然语言参考图清单。禁止为具体项目硬编码固定参考图数量；数量必须从当前 ACTIVE A4 stage map、A4 table_node、A3 ACTIVE 资产池、A0/A2 当前 `video_task_id` 的人物 / 道具空间真值动态计算。凡当前任务内剧本明确可见、参与空间调度、承担对照、被操作 / 移动 / 持有 / 承载关系的配角与道具，只要总数不超过 16 张，就必须全量传入真实 `image_paths`。

**B1-B5 剪枝边界硬锁**：本节剪枝只在黑白 3x3 分镜生图模型的 16 张参考图上限被超过时触发，不得传递为 B6/B8 视频阶段删减参考图的依据。被剪枝资产不得从 A0 `active_asset_pool`、`video_task_mapping[video_task_id].reference_requirements` 或 B8 视频参考候选中删除；B8 必须重新从 A0 ACTIVE 资产池、当前 `video_task_id` 引用需求、B1-B5 `pruned_asset_text_payload_manifest` 和最终 `@STORYBOARD_GRID` 组装视频参考图。若 B8 因沿用 B1-B5 剪枝清单导致人物 / 场景 / 道具 / 光影 / 当前分镜参考缺失，触发 `[E12: Video Reference Coverage Failure]`。

## 占位符命名空间

进入最终 task_description 前必须建立刚性占位符：

```text
@STAGE_MAP_VISUAL = 当前分镜生图任务所绑定 video_task_id 的唯一舞台定位图 media_node，仅作为 Layout / 结构 / blocking 参考锁
@IMAGE_ASSET_N = 彩色视觉资产图，按物理 image_paths 顺序编号，N 从 1 开始；每个实际传入 image_paths 的 N 必须绑定 asset_type、identity_token / prop_token、asset_image_path；被剪枝资产不得占用 N 编号，必须进入 [Pruned Asset Text Payload] 并记录 asset_type、identity_token / prop_token、asset_image_path、剪枝原因和空间字段
@STORYBOARD_GRID = 黑白 3x3 分镜图，仅在视频阶段出现；其 video-stage image_paths 位置由 B8 final_reference_order_policy 决定，禁止硬编码为倒数第二位
```

禁止使用 `@参考图N`、`@资产图N`、`@分镜图` 等旧称。

黑白分镜阶段：`@STAGE_MAP_VISUAL` 对应 `image_paths[0]`；`@IMAGE_ASSET_1..N` 对应 `image_paths[1..N]`。`Reference Mention Map` 与真实 `Reference image paths` 必须绝对对齐。

## B2 黑白 3x3 生成

必须生成单张全景 3x3、共 9 个面板的整体宫格黑白分镜大图。每张黑白 3x3 是一个独立图片生成任务，但它必须绑定 `视频任务切分计划` 中一个且仅一个 10-15 秒 `video_task_id`，并使用该 `video_task_id` 对应的唯一舞台定位图；不得用一张黑白分镜覆盖多个 `video_task_id`。

9 个 Panel 的阅读顺序必须固定为从左到右、从上到下：第一行 Panel 1 / Panel 2 / Panel 3，第二行 Panel 4 / Panel 5 / Panel 6，第三行 Panel 7 / Panel 8 / Panel 9。每个格内必须写清顺序文字 `Panel 1` 至 `Panel 9`，顺序文字只作为分镜索引标签，不得替代空间字段、动作描述或视频提示词中的结构化 Panel 数据。

跨任务连续性采用【Panel 9 -> 下一任务 Panel 1 衔接桥】：同一集内 `EPxx-VTnn Panel 9` 必须写入 `continuity_handoff`，并成为 `EPxx-VT(n+1) Panel 1 continuity_start`；跨集边界时，上一集最后一个 VT 的 Panel 9 必须成为下一集 `EPxx+1-VT01 Panel 1 continuity_start`。该“相等”指起始连续状态相等：角色位置、动作余势、视线方向、道具状态、情绪余韵、声音尾音、`screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_direction_text`、`camera_screen_position_text`、`movement_direction_text` 必须被结构化继承。下一任务仍必须生成新的舞台定位图、新的黑白 3x3 分镜图和新的提示词段；Panel 9 只能提供 continuity handoff，不得被下一任务复用为 `@STORYBOARD_GRID` 或替代下一任务 Panel 1 图像。

## 画风与物理参数

- 模型与物理参数：`image2 / 1k / 16:9 / medium`（画质：中）。
- **黑白分镜 image2 参数硬锁**：B1-B5 黑白 3x3 分镜派单时，`[MANDATORY DISPATCH PAYLOAD]` 与 image agent `task_description` 必须显式写入以下机器字段，缺一不可：

```yaml
model: gpt-image-2
model_alias: image2
resolution: 1k
quality: medium
aspect_ratio: 16:9
```

- **禁止参数漂移**：黑白分镜阶段不得省略 `quality: medium` / `画质：中`，不得把旧版 `image2 / 4k / 16:9 / low` 或 A3 视觉资产的 `image2 / 1k / 16:9 / high` 参数继承到 B1-B5。若派单载荷、冻结记录、QC 记录或实际生成 metadata 中出现 `resolution: 4k`、`quality: low`、`quality: high`、`画质：低`、`画质：高`、`low quality` 或 `high quality`，立即判定 `[E09: Storyboard Model Parameter Drift]`，该黑白分镜不得进入 B5 PASS，也不得被 B6/B8 作为 `@STORYBOARD_GRID` 读取，必须用 `resolution: 1k`、`quality: medium`、`aspect_ratio: 16:9` 重新派单。
- 输出必须是单张横版 16:9 黑白 3x3 整体宫格，3 列 x 3 行 = 9 个面板，不是 9 张独立图片；每个 Panel 内部有效画面也必须保持 16:9，允许黑白 letterbox / pillarbox padding，禁止改成 21:9、4:3 或竖幅。
- 每格只表达一个动作关键帧，并保留清晰顺序文字：第一行 `Panel 1`、`Panel 2`、`Panel 3`；第二行 `Panel 4`、`Panel 5`、`Panel 6`；第三行 `Panel 7`、`Panel 8`、`Panel 9`。顺序文字必须位于格内不遮挡主体的位置，必须可读。
- 格网边界仅允许 1px 黑色固态分割线（#000000）。画风强制锁定为 Pure B&W Line-Blockout Drawing：纯白背景、纯黑线稿，角色统一使用简约线框人偶 / 火柴人动作模型（Stick-Figure / Wireframe Action Model），仅表达站位、动作、视线、运动轨迹、镜头关系和道具运动；允许使用动作线、速度线、轨迹线、冲击线、聚焦线、颤抖线、震动线和视线线表达动作方向、运动强度、注意力焦点与情绪张力。禁止出现面部细节、服装细节、材质表现、颜色、对白气泡、Logo、UI元素、灰度渐变、纹理、阴影、体积感、写实遮蔽或任何照片级渲染特征。除 `Panel 1` 至 `Panel 9` 顺序文字外，禁止出现其他文字。
- 必须启用基于三维摄影机距离的刚性线宽协议（Rigid Camera-Distance Line Weight Protocol）：前景 / 近景资产（Camera Distance ≤ 20）统一使用 3px 纯黑粗实线；中景主要动作资产统一使用 2px 纯黑实线；背景环境结构统一使用 1px 纯黑细线。线宽层级必须依据摄影机空间距离计算，不得依据屏幕坐标、视觉大小或主观判断调整。任何出现灰度、渐变、纹理、阴影、体积塑形、写实遮蔽或违反线宽协议的情况，均判定 QC FAIL。

## Stage Map Same-Source Spatial Payload

黑白分镜 task_description 必须建立 `[Stage Map Same-Source Spatial Payload]`，逐一声明：`source_space_truth_node`、`source_space_truth_version`、`source_coordinate_camera_baseline_section: 坐标与摄影机基准`、`stage_map_media_node`、`stage_map_table_node`、`table_node_version`、`video_task_id`、`reference_validity_chain`。该块必须说明舞台定位图 media_node、A4 table_node、A2 `空间真值调用中心.坐标与摄影机基准` 是同一空间真值的三种表达；Panel 1-9 的全部坐标、朝向、屏幕方位、摄影机位置 / 目标 / 焦段、自然语言方位描述都必须从这一同源载荷复制，不得由黑白图模型临场推断。

黑白分镜必须明确说明自己参考舞台定位图中的哪些关键信息，且这些关键信息必须能在 `坐标与摄影机基准` 中找到对应源字段：1) `coordinate_system` 与 `stage_origin_note`，用于锁定 100x100 平面和画面方向；2) 每个角色的 `stage_position_xy` / `stage_position_xyz`，用于锁定人物色块 / 线框人偶所在位置；3) A4 `character_shape_color_map`，用于继承人物“方形/矩形色块 + 红橙黄绿青蓝紫粉白顺序”的身份与位置编号；4) A4 `prop_shape_color_map`，用于继承道具“圆形色块 + 红橙黄绿青蓝紫粉白顺序”的道具与位置编号；5) `facing_target_xy` / `facing_target_xyz` 与 `facing_direction_text`，用于锁定朝向箭头和身体朝向；6) `screen_position` 与 `screen_direction_text`，用于锁定画面左 / 中 / 右、前 / 后层次；7) `camera_position_xyz`、`camera_target_xyz`、`camera_direction_text`、`camera_screen_position_text`、`focal_length_mm`，用于锁定机位、视线、景别和线宽距离层级；8) `eyeline` 与 `distance_relation`，用于锁定人物互看 / 看物 / 遮挡距离；9) `movement_path`、`movement_path_xyz` 与 `movement_direction_text`，用于锁定动作线、速度线和 Panel 间运动轨迹；10) 道具 `stage_position_xy`、`stage_position_xyz`、`owner_character`、`attachment_point`、`prop_spatial_direction_text`、`prop_movement_direction_text`，用于锁定道具与人物关系。

**禁止舞台图引用压缩 / No Stage-Map Summary Shortcut**：`[Stage Map Same-Source Spatial Payload]` 不能只写“参考舞台定位图 / 坐标见 A4 / 已继承 table_node / 舞台图锁定站位”。它必须把 A4 的 100x100 坐标系说明、形状颜色映射说明、紫白色箭头语义、每个角色/道具的坐标、朝向、摄影机、Eyeline、距离、运动路径与自然语言方位字段逐 Panel 展开。每个 Panel 的 `source_panel_from_storyboard_grid` 与 `[Panel Spatial Lock]` 必须能直接在当前 task_description 中读懂，不依赖读者再打开 A4 表格猜测。若只保留概括句或只列 A4 节点名，判定 `[E08: Chain Freeze Violation]` + `[E13: Link Interface Contract Failure]`，旧黑白分镜不得进入 B5 PASS 或 B6/B8。

`[Stage Map Same-Source Spatial Payload]` 必须按 Panel 1 至 Panel 9 列出每格全部角色和关键道具的同源字段。角色字段至少包含：`identity_token`、`asset_ref_id`、`asset_image_path`、`shape: square`、`color_name`、`color_index`、`stage_position_xy`、`stage_position_xyz`、`facing_target_xy`、`facing_target_xyz`、`screen_position`、`screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_facing`、`camera_position_xyz`、`camera_target_xyz`、`camera_direction_text`、`camera_screen_position_text`、`focal_length_mm`、`eyeline`、`distance_relation`、`movement_path`、`movement_path_xyz`、`movement_direction_text`、`state_action`。道具字段至少包含：`prop_token`、`asset_ref_id`、`asset_image_path`、`shape: circle`、`color_name`、`color_index`、`stage_position_xy`、`stage_position_xyz`、`prop_spatial_direction_text`、`attachment_point`、`owner_character`、`visibility_state`、`movement_path`、`movement_path_xyz`、`prop_movement_direction_text`。所有坐标必须保持带 X/Y/Z 键名的对象格式：二维字段为 `{"x": number, "y": number}`，三维字段为 `{"x": number, "y": number, "z": number}`；禁止压缩成裸数字、数组、逗号字符串或只保留二维坐标而丢失 `stage_position_xyz`。

## Dialogue Delivery & Capability Risk Payload

黑白分镜 task_description 必须逐 Panel 继承 A0/A2 的 `dialogue_intent_delivery_matrix`、`video_model_capability_risk_register` 与 `performance_substitution_plan`。该块至少包含：`dialogue_delivery_mode_payload`、`model_capability_risk_payload`、`performance_substitution_payload`、对应 `risk_id`、对应 `dialogue_id`、替代表现策略、替代后剧情功能、声音锚点、道具结果状态。黑白分镜不得重新引入 A0 已判定 `substitution_required: true` 的字面精细动作；只能把它转成可画的动作起势、结果道具、反应镜头、声音打点或镜头切分提示。该块服务 B6 `[Panel Execution Chain]`，不得被剪枝。

## Character Count Lock

黑白分镜 task_description 必须建立 `[Character Count Lock]`，并从当前 `video_task_id` 的 A4 table_node / A0 `video_task_mapping` 逐字继承：`allowed_visible_characters`、`allowed_visible_character_count`、`allowed_character_nodes`、`forbidden_extra_people`、`character_count_lock_source`、`character_count_lock_status`。每个 Panel 必须声明 `visible_characters`、`offscreen_characters`、`occluded_characters`，三者并集必须等于 `allowed_visible_characters`，不得出现额外角色名或匿名人群。所有结构化角色列表必须使用中文角色全名；禁止把中文角色名改成中文短名、昵称、省略称、拼音首字母、英文缩写、英文代号、罗马字、identity_token 片段或任意非全名标签。每个 Panel 画面中的火柴人 / 线框人偶 / 人形剪影数量必须等于该 Panel 的 `visible_characters` 数量；被标记为 `offscreen` 或 `occluded` 的角色不得以额外人形方式出现在画面边缘。若需要表现评审席、工作人员或背景人群，只能使用已列入 `allowed_visible_characters` 的角色，不得补群众、额外评委、额外工作人员、游客、路人或背景剪影。合并人物参考图必须在锁内拆解为具体已声明角色或已声明合并节点，并说明该合并图只用于身份识别，不允许扩展更多人物。

## Panel Spatial Lock

每个 Panel 必须列出本段全部角色，即使在背景、半遮挡或暂不行动。Panel 1 至 Panel 9 必须逐格继承 `空间真值调用中心` 的 `Panel Character Spatial Matrix`、当前分镜生图任务所绑定 `video_task_id` 的舞台定位图 table_node、A4 `[Character Count Lock]`、A4 `character_shape_color_map`、A4 `prop_shape_color_map` 与 A2 `[Temporal_Anchor]`，不得改写成自然语言概要。每个角色必须保留：`identity_token`、`asset_ref_id`、`asset_image_path`、`shape: square`、`color_name`、`color_index`、`stage_position_xy`、`stage_position_xyz`、`facing_target_xy`、`facing_target_xyz`、`gaze_logic`、`screen_position`、`screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_facing`、`camera_position_xyz`、`camera_target_xyz`、`camera_direction_text`、`camera_screen_position_text`、`focal_length_mm`、`eyeline`、`distance_relation`、`movement_path`、`movement_path_xyz`、`movement_direction_text`、`state_action`、`previous_emotion_state`、`current_emotion_state`、`next_emotion_target`、`transition_logic`、`visibility_state`、`panel_duration`、`key_action_timestamp`。`stage_position_xyz` 不得标记为可选；平面角色默认 `z: 0`，多层空间写真实 Z 层级。

道具必须包含 `prop_token`、`asset_ref_id`、`asset_image_path`、`shape: circle`、`color_name`、`color_index`、`stage_position_xy`、`stage_position_xyz`、`prop_spatial_direction_text`、`attachment_point`、`owner_character`、`visibility_state`、`movement_path`、`movement_path_xyz`、`prop_movement_direction_text`。道具 `stage_position_xyz` 不得缺失；平面道具默认 `z: 0`，桌面、手持、架上等高度层级必须写真实 Z 值。

角色与道具坐标必须清洗为带键 JSON 对象 `{"x": number, "y": number}`，并且必须同步保留三维对象 `stage_position_xyz: {"x": number, "y": number, "z": number}`；平面舞台对象默认 `z: 0`，有高度层级时写真实 Z 值。摄影机坐标必须为三维带键 JSON 对象 `{"x": number, "y": number, "z": number}`。禁止使用 `[x, y]`、`[x, y, z]`、`x,y`、`x/y/z`、裸数字、只有二维无三维、或只有数字没有 X/Y/Z 键名的形式。`camera_facing` 必须是明确方向向量 / 目标点描述，禁止只写“看向角色”“镜头对准冲突”等散文。`screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_direction_text`、`camera_screen_position_text`、`movement_direction_text` 和道具方位字段是结构化生成约束，不得画成可见文字；最终黑白图除 `Panel 1` 至 `Panel 9` 顺序标签外禁止出现任何坐标或字段文字。

## Panel 9 to Next Panel 1 Continuity Bridge

每张黑白 3x3 的 Panel 9 必须输出结构化 `continuity_handoff`，包含角色 / 道具坐标、朝向、屏幕方位、镜头状态、动作余势、视线方向、声音尾音、情绪余韵和全部 `_text` 方位字段。若存在下一 VT，下一 VT 的 Panel 1 必须写入 `continuity_start` 并声明来源为上一 VT 的 `continuity_handoff`；若处于集末，下一集首个 VT 的 Panel 1 必须同样继承该 `continuity_handoff`。该继承发生在 task_description / 空间字段层，不能通过复用上一张黑白分镜图偷懒实现。

## B1-B5 全链路冻结登记

B1-B5 每个黑白 3x3 分镜任务在调用 image agent 前，必须把当前任务的 `[MANDATORY DISPATCH PAYLOAD]` 写入 A0 `[SSC_RUNTIME_LEDGER].dispatch_payload_freeze_records` 的预冻结草稿；B5 QC PASS 后必须将其升级为正式冻结记录，并同步写入 `[SSC_RUNTIME_LEDGER].chain_freeze_manifest`。冻结对象至少包含：黑白分镜 `task_description` 全文、`[Stage Map Same-Source Spatial Payload]`、`[Dialogue Delivery & Capability Risk Payload]`、`[Character Count Lock]`、`[Panel 9 to Next Panel 1 Continuity Bridge]`、`Reference Mention Map`、真实 `image_paths` 顺序、`pruned_asset_text_payload_manifest`、输出黑白 3x3 路径、`panel9_continuity_handoff` 与 `next_panel1_continuity_start`。

每条 B1-B5 冻结记录必须包含：`freeze_id`、`stage: B1-B5`、`video_task_id`、`object_type: storyboard_dispatch_payload | storyboard_grid_output | reference_mention_map | continuity_bridge`、`object_name_or_node`、`source_a3_scope_manifest_freeze_id`、`source_stage_map_freeze_id`、`source_space_truth_freeze_id`、`a3_completion_status: PASS`、`a4_generated_after_a3_manifest: true`、`upstream_freeze_ids`、`content_hash_or_length_snapshot`、`allowed_mutation_scope: [真实输出路径填充, canvas node id 填充, QC PASS 状态写入, 下游引用 id 填充]`、`mutation_owner: B5_QC`、`qc_status`。B5 QC PASS 后，必须把 B1-B5 相关 `freeze_id` 回填到当前 `video_task_mapping[video_task_id].dispatch_payload_freeze_ids`，并确保 B6/B8 可通过该索引反查 `@STORYBOARD_GRID`、引用映射和连续性桥的冻结快照。缺少上述冻结记录或缺少任务映射索引时，视为黑白分镜链路未冻结，禁止 B6 读取该分镜作为 `@STORYBOARD_GRID`，触发 `[E08: Chain Freeze Violation]`。

冻结后，B6/B8 只能读取 `status: ACTIVE` 且存在 B1-B5 `freeze_id` 的黑白 3x3 分镜、引用映射和连续性桥。任何重做黑白分镜必须将旧 `storyboard_grid_node/path`、旧 `task_description`、旧引用映射与旧连续性桥标记为 `[DEPRECATED_OLD_VERSION]`，保留旧冻结快照，新版本必须生成新的 `freeze_id`；禁止原地覆盖旧分镜路径或继续让下游引用旧版本。

## B5 分镜登记闭环

黑白 3x3 分镜图生成并通过 B5 QC 后，必须立即回写 A0 `[SSC_RUNTIME_LEDGER].video_task_mapping[video_task_id]`：`storyboard_grid_node`、`storyboard_grid_path`、`storyboard_grid_status: ACTIVE`、`storyboard_source_stage_map_media_node`、`storyboard_source_stage_map_table_node`、`source_coordinate_camera_baseline_section: 坐标与摄影机基准`、`storyboard_reference_image_paths`、`storyboard_reference_mention_map`、`pruned_asset_text_payload_manifest`、`reference_validity_status: PASS`、`lineage_continuity_status: PASS`、`panel_count: 9`、`panel_order: Panel 1 -> Panel 9`、`allowed_visible_characters`、`allowed_visible_character_count`、`forbidden_extra_people`、`character_count_lock_status: PASS`、`panel_character_visibility_matrix`、`panel9_continuity_handoff`、`next_panel1_continuity_start`、`panel9_to_next_panel1_lock`。同时向 `[SSC_RUNTIME_LEDGER].lineage_audit_chain` 追加 B1-B5 记录，包含输入舞台定位图、A2 `坐标与摄影机基准` 源字段、实际传入 `image_paths`、被剪枝资产清单、模型参数、输出黑白 3x3 路径、引用有效性预检结果、同源空间载荷字段和 QC 结果。若重做黑白分镜，旧 `storyboard_grid_node/path` 必须标记 `[DEPRECATED_OLD_VERSION]` 并从当前 `video_task_mapping` 中解除 ACTIVE 状态，禁止 B6/B8 继续作为 `@STORYBOARD_GRID` 引用。

## 引用可解析性预检

B5 预审前必须执行 `Reference Resolve Preflight`：

- `@STAGE_MAP_VISUAL` 必须解析到当前分镜生图任务所绑定 `video_task_id` 的唯一舞台定位图 media_node。
- `@IMAGE_ASSET_N` 必须解析到对应彩色视觉资产。
