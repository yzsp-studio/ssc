# A3 视觉资产

本文件由 `00-强制读取索引.md` 强制触发。进入 A3 前必须读取本文件；未读取即触发 `[E07: Required Reference Missing]`。

## Entry Guard

执行 A3 前必须先完成外部 Skill 加载询问，然后验证当前段落存在并通过 QC 的：

- `影视工业体系数据中心 — [集数][段落编号][场景名]`
- `故事板概要 — [集数][段落编号][场景名]`
- `场景调度表 — [集数][段落编号][场景名]`
- `空间真值调用中心 — [集数][段落编号][场景名]`

任一缺失，触发 `[E01: Missing Script/Assets]`，回退至 A0/A1/A2 修复。A3 必须读取并消费 A0 的角色 / 道具资产决策、`scene_cinematography_profile` 槽位、`performance_substitution_plan`、`video_task_mapping` 与冻结账本；缺任一消费记录视为空链路。严禁依据对话上下文、旧缓存或用户模糊指令跳过门禁直接生成参考图。

生成舞台定位图前，允许范围内视觉资产必须先完成并落画布。

## A3 完整资产范围锁 / Asset Completion Barrier

A3 不允许把“某一个道具已生成”“某几个参考图已有”误判为“视觉资产阶段完成”。进入 A4 前必须先生成并冻结 `A3_SCOPE_MANIFEST`，明确本轮制作范围内所有应完成的美术资产参考图，并逐项给出 `status: ACTIVE | DEPRECATED_OLD_VERSION | NOT_REQUIRED_WITH_REASON | PENDING | FAIL`。

默认规则：若用户没有用明确文字授权“只做当前 video_task_id 的最小资产集”，A3 范围必须覆盖当前段落 A0 `character_asset_decision`、`prop_asset_decision`、场景参考图、可选光影决策中所有 `必出 / 建议出 / 可合并但需要合并图` 的视觉资产；不得因为当前先做一个视频，就自动缩小为单个任务的局部资产。全自动模式不等于自动缩小范围。

若确需只为某个 `video_task_id` 生产最小资产集，必须在 A0 与 A3 同时写明：`a3_scope_mode: task_only_explicit`、`scope_authorization_source: user_explicit`、`included_asset_requirements`、`excluded_segment_assets_with_reason`、`downstream_risk_note`。没有该授权记录时，`task_only` 范围无效，A4 Entry Guard 必须判 FAIL 并回到 A3。

`A3_SCOPE_MANIFEST` 必须至少包含：

```yaml
a3_scope_mode: segment_full | task_only_explicit
scope_authorization_source: user_explicit | segment_default
scope_video_task_ids: [<video_task_id 或 segment_all>]
required_scene_assets: []
required_character_assets: []
required_prop_assets: []
required_merged_character_grids: []
required_merged_prop_grids: []
optional_lighting_assets: []
asset_rows:
  - asset_name: <中文全名>
    asset_type: character | scene | prop | lighting | merged_character_reference_grid | merged_prop_reference_grid
    decision_source: A0.character_asset_decision | A0.prop_asset_decision | A2.reference_requirements
    required_status: 必出 | 建议出 | 可合并 | 不出
    production_status: ACTIVE | DEPRECATED_OLD_VERSION | NOT_REQUIRED_WITH_REASON | PENDING | FAIL
    asset_image_path: <真实路径或 pending>
    freeze_id: <冻结编号或 pending>
    reason_if_not_required: <仅 NOT_REQUIRED_WITH_REASON 时允许>
completion_check:
  pending_assets: []
  failed_assets: []
  deprecated_without_replacement: []
  all_required_assets_active_or_not_required: true | false
  a3_completion_status: PASS | FAIL
```

A3 Exit Guard：只有 `completion_check.pending_assets == []`、`failed_assets == []`、`deprecated_without_replacement == []` 且 `all_required_assets_active_or_not_required == true` 时，`a3_completion_status` 才允许写 PASS。任何 `PENDING / FAIL / deprecated_without_replacement` 都禁止进入 A4，并触发 `[E16: A3 Asset Completion Barrier Failure]`。禁止用 `resolved_asset_ids != []`、局部资产可用、或某个单项 `coverage_status: PASS` 替代完整范围检查。

## 允许资产

只允许生成：人物参考图、场景参考图、关键道具参考图、可选光影参考图，以及由 A0 判定触发的角色合并参考图 / 道具合并参考图。服装、妆造、表情包、姿势库、材质拆解、气氛小样不得单独新增。

## A3 资产登记契约

每次 A3 生成或修复任一视觉资产后，必须立即回写 A0 `[SSC_RUNTIME_LEDGER]`，禁止只把路径留在聊天上下文或分散文档里。每个进入 `active_asset_pool` 的资产条目必须包含：

```text
{
  asset_id: <canvas node id 或稳定资产编号>,
  asset_type: character | scene | prop | lighting | merged_character_reference_grid | merged_prop_reference_grid,
  asset_image_path: <真实可解析路径>,
  source_stage: A3,
  source_node: <生成该资产的派单 / canvas node>,
  script_source_node: <A0.script_source_node>,
  episode_segment_scene: <集数 + 段落编号 + 场景名>,
  identity_token: <人物资产必填；非人物为空>,
  prop_token: <道具资产必填；非道具为空>,
  video_task_id: <若只服务特定 10-15 秒任务则填写；全段通用则写 segment_global>,
  reference_role: character_identity | scene_environment | prop_identity | lighting_mood | merged_character_identity | merged_prop_identity,
  status: ACTIVE,
  generated_at: <时间戳>,
  replacement_of: <若为修复重做则填写旧资产 id，否则为空>
}
```

A3 同时必须向 `[SSC_RUNTIME_LEDGER].lineage_audit_chain` 追加本次 image task 的摘要：输入 A1/A2/空间真值节点、`Required_References_Read`、真实 `image_paths`、模型参数、输出路径和 QC 结果。每次 A3 派单前的 `[MANDATORY DISPATCH PAYLOAD]`、外部 Skill 注入结果、资产登记结果和 `A3_SCOPE_MANIFEST` 通过 QC 后，必须写入 `[SSC_RUNTIME_LEDGER].dispatch_payload_freeze_records` 与 `chain_freeze_manifest`，记录 `freeze_id`、资产类型、真实路径、source_node、content_hash_or_length_snapshot、allowed_mutation_scope、`a3_scope_mode`、`a3_completion_status`；同时必须把 A3 相关 `freeze_id` 回填到消费该资产的 `video_task_mapping[video_task_id].dispatch_payload_freeze_ids`，并把 `A3_SCOPE_MANIFEST.freeze_id` 回填到每个受影响 `video_task_id.a3_scope_manifest_ref`、`source_a3_scope_manifest_freeze_id`、`a3_scope_mode`、`a3_completion_status`；全段通用资产回填到本段全部受影响任务。A3 完成资产登记后，必须按 `video_task_id` 反写 A0 `reference_requirements.resolved_asset_ids`、`missing_asset_requirements`、`coverage_status`、`producer_stage: A3`，并同步更新 `upstream_producer_map` / `downstream_consumer_map`：已生成且 ACTIVE 的人物 / 场景 / 道具 / 光影资产写入 `resolved_asset_ids`，仍缺失的必需资产保留在 `missing_asset_requirements`，此时 `coverage_status` 只能是 `pending` 或 `FAIL`，不得写 PASS。只有 `required_*` 全部被 ACTIVE 资产或合并参考图覆盖，且 `resolved_asset_ids != []`，才允许写 `coverage_status: PASS`。冻结后下游只能原样引用资产路径 / token / 冻结载荷，不得重新口述、摘要、换词或把人物 / 场景 / 道具参考图改成剧情动作图。若 A3 重做旧资产，必须先将旧资产从 `active_asset_pool` 移入 `deprecated_asset_pool`，记录废弃原因、替代资产和 `[DEPRECATED_OLD_VERSION]`，再登记新资产为 ACTIVE 并生成新的 freeze_id，并重新计算所有受影响 `video_task_id.reference_requirements`；下游 A4/B1/B6/B8 只能读取 `active_asset_pool` 中 `status: ACTIVE` 且有冻结记录的资产。若 A3 资产登记完成但未回写 `reference_requirements` 或把 `resolved_asset_ids == []` 判为 PASS，触发 `[E13: Link Interface Contract Failure]` 或 `[E14: Empty Upstream Data / Pending-as-PASS Failure]`，禁止进入 A4。

## 场景参考图派发契约

模型参数：`image2 / 1k / 16:9 / high`。

数据源：A2 `Global Environment Context` 与 `场景空间结构`。

必须生成专业场景标准设定图，纯空镜环境参考，包含 4 个不同机位场景分镜区块，严禁出现人物、动物或动态模糊。整体横版 16:9。4 个分镜区块：正对主展示面的水平平视、侧斜 45 度小俯角、全域大俯角鸟瞰、低位小仰角对准核心采光 / 景观面。

必须继承：时代背景、建筑级别与阶级、墙面 / 地面 / 家具 / 金属材质、全局天气 / 时辰 / 烛光 / 火光基调、主光方向、辅光比、色温、明暗过渡与对比度。使用 ARRI ALEXA 65 摄影基准。

场景参考图生成前必须执行“场景摄影参数继承门”：常规模式下用 `question` 提醒用户是否加载光影、色彩、氛围、质感、摄影机参数、光圈、景深、镜头参数等摄影相关能力；全自动模式下自动加载当前阶段相关能力并写入 A0 `[SSC_RUNTIME_LEDGER].external_skill_load_log`。场景参考图完成后，必须回写 A0 `scene_cinematography_profile`，至少记录 `lighting_direction`、`key_fill_ratio`、`color_temperature`、`contrast_level`、`atmosphere`、`material_texture_response`、`camera_system`、`lens_mm`、`aperture_or_t_stop`、`depth_of_field`、`iso_or_exposure_logic`、`dynamic_range`、`color_science`、`scene_reference_image_path`，供 B6/B8 逐项继承。

## 人物参考图派发契约

模型参数：`image2 / 1k / 16:9 / high`。

数据源：A1 人物面部三庭五眼结构表。

必须生成专业角色标准设定图，完整全身体态，从头到脚无遮挡。纯中灰 `#7c7c7c` 背景。多视角包含纯正面 A-Pose、纯侧面、纯背面，并在画面一侧融入锁骨以上正脸微调头部特写，真实人类面部特征，保留原生皮肤肌理与自然生理细微瑕疵，面部存在自然轻微不对称，无过度磨皮与理想化美颜。所有视角身份、面孔、服装、发型、身材必须一致。

禁止海报叙事构图，禁止混入当前段落剧情动作、叙事道具和特定行为。人物参考图用于身份和外貌真值，不用于表演当前剧情。

必须继承：年龄、朝代 / 背景、府邸 / 门第层级、职位 / 身份、人设性格、面部骨骼、三庭五眼、眉弓、眼距、鼻梁、颧骨、下颌、脸型、真实皮肤瑕疵、服装阶级和电影级摄影参数。

## 角色合并参考图协议

当 A0 `character_asset_decision` 判定多个角色为“建议出 / 可合并”，且同组 `merge_candidate_group` 需要降低视频参考图槽位压力时，A3 可生成 `asset_type: merged_character_reference_grid` 的角色合并参考图。该图只用于多人身份识别，不替代单人主角必出参考图。

生成规则：

- 2 角色：1×2；3 角色：1×3；4 角色：2×2；5 角色：2×3；6 角色：2×3；7 角色：3×3 占 7 格，其余空位；8 角色：3×3 占 8 格，其余空位；9 角色：3×3。
- 阅读顺序固定为从左到右、从上到下；角色与颜色一一绑定。
- 颜色顺序固定为红、橙、黄、绿、青、蓝、紫、粉、白；白色框必须带深色描边。
- 每格必须用对应颜色框选该角色，并在框旁或框内写清晰中文角色全名；禁止使用中文短名、昵称、省略称、拼音首字母、英文缩写、英文代号、罗马字、identity_token 片段或任意非全名标签。
- 7 / 8 角色产生的空格必须保持为空或中性占位，不得生成额外人物、剪影或干扰主体。
- 合并图中每个角色应保持面部、发型、服装和身形可识别，不得层叠、混脸、互相遮挡或变成剧情分镜。
- 登记到 A0 时必须记录 `merged_from_asset_ids`、每个颜色框对应中文角色全名、`grid_layout`、`read_order`、`reference_role: merged_character_identity`；登记字段中的可读名称同样不得短名化、缩写化或 token 化。

## 关键道具参考图契约

模型参数：`image2 / 1k / 16:9 / high`。

数据源：A2 道具坐标表与 A1 道具信息提取表。

必须生成孤立物体置中、多角度展示的道具标准设定图，纯中灰背景，包含正、侧、45 度俯视。禁止人物手持、场景置入或文字标签。

必须继承道具名称、功能分类、材质构成、表面纹理、做旧程度、使用痕迹、氧化 / 包浆状态、剧情作用和角色绑定关系。

若 A0 `video_model_capability_risk_register` 将某个高风险动作判定为 `substitution_strategy: 静态道具替代`，A3 必须把替代后的结果状态纳入关键道具参考图需求，例如“已画叉纸张 / 已盖章文件 / 已破损道具 / 已撕裂结果”。该道具图仍属于 `asset_type: prop`，不得新增资产类别；但登记时必须在 `prop_token` 或道具状态字段中标明 `substitution_result_state`，供 A2/B6/B8 引用。

## 道具合并参考图协议

当 A0 `prop_asset_decision` 判定多个道具为“必出 / 建议出 / 可合并”且 `merge_allowed: true` 时，A3 可生成 `asset_type: merged_prop_reference_grid` 的道具合并参考图。该图只用于道具外观与一致性识别，不得牺牲关键证据细节。

可合并条件：道具外形清楚、无必须阅读的小字 / 印章 / 纹理证据、不承担机关细节、不因缩小而失去剧情识别意义。同组道具只需在视频中保持外观一致时可合并。

不可合并条件：关键证据道具、带可读文字或印章的道具、细小纹理决定剧情的道具、机关结构或破损状态影响剧情的道具、形态易与其他道具混淆的道具。此类必须单独出关键道具参考图。

生成规则：

- 2 道具：1×2；3 道具：1×3；4 道具：2×2；5 道具：2×3；6 道具：2×3；7 道具：3×3 占 7 格，其余空位；8 道具：3×3 占 8 格，其余空位；9 道具：3×3。
- 阅读顺序固定为从左到右、从上到下；道具与颜色一一绑定。
- 颜色顺序固定为红、橙、黄、绿、青、蓝、紫、粉、白；白色框必须带深色描边。
- 每格必须用对应颜色框选该道具，并在框旁或框内写清晰中文道具名。
- 7 / 8 道具产生的空格必须保持为空或中性占位，不得生成额外道具、装饰物或误导性主体。
- 登记到 A0 时必须记录 `merged_from_asset_ids`、每个颜色框对应道具名、`grid_layout`、`read_order`、`reference_role: merged_prop_identity`。

## 可选光影参考图契约

模型参数：`image2 / 1k / 16:9 / high`。

数据源：A2 Global Environment Context，仅供视频模型参考，视频阶段顺序固定放最后一位。

必须是纯粹光影氛围参考图，只展示光照分布、阴影形状、色温过渡与反差层级。允许包含场景空间作为载体，但核心目标是锁定光影质感。禁止清晰人物面部、服装细节或可辨识叙事动作。

## A3 FAIL

任一参考图派发载荷缺失占位符、混入剧情动作、越权写入非本节点信息、参考图未落画布、路径不可解析、资产类型越界、未登记到 A0 `[SSC_RUNTIME_LEDGER].active_asset_pool`、缺少 `asset_type` / `asset_image_path` / `script_source_node` / `reference_role` / `status: ACTIVE`、人物资产缺少 `identity_token`、道具资产缺少 `prop_token`、A0 要求 `静态道具替代` 但 A3 未生成或未登记替代结果状态道具、合并参考图缺少 `merged_from_asset_ids` / `grid_layout` / 颜色-名称映射 / 中文标签 / 白框深色描边规则、7/8 格合并图空位出现额外主体、场景参考图缺少 `scene_cinematography_profile` 或未回写 A0、未向 `lineage_audit_chain` 写入派单摘要，均判定 FAIL。A3 派单载荷、外部 Skill 注入结果或资产登记结果缺少 `dispatch_payload_freeze_records` / `chain_freeze_manifest` / `freeze_id` / `content_hash_or_length_snapshot` / `allowed_mutation_scope` 时，触发 `[E08: Chain Freeze Violation]`，禁止进入 A4。
