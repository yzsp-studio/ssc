# A4 舞台定位图

本文件由 `00-强制读取索引.md` 强制触发。进入 A4 前必须读取本文件；未读取即触发 `[E07: Required Reference Missing]`。

## 引用边界

舞台定位图必须把当前任务相关资产参考图作为真实 reference image：当前段落场景参考图、参与本 10-15 秒任务的全部人物参考图、参与空间调度的关键道具参考图。可选光影参考图和黑白分镜图不得传入舞台定位图。场景参考图只用于场景结构降维；人物参考图只用于角色身份、身形比例和色块标签对应；关键道具参考图只用于道具身份和尺寸类别对应。坐标、朝向、镜头方向、Eyeline 和相对距离仍以 `空间真值调用中心` 与 table_node 为唯一几何真值，禁止由资产参考图反推或改写空间真值。

每一张舞台定位图只对应 `视频任务切分计划` 中一个 10-15 秒视频任务，不得跨多个视频任务共用。若一个段落拆成多个 10-15 秒任务，必须为每个任务分别生成对应舞台定位图。

## 派单前必做

0. 必须读取 A0 / A3 中已冻结的 `A3_SCOPE_MANIFEST`，并验证 `completion_check.a3_completion_status: PASS`、`pending_assets: []`、`failed_assets: []`、`deprecated_without_replacement: []`、`all_required_assets_active_or_not_required: true`。若缺少 `A3_SCOPE_MANIFEST`、`a3_scope_mode` 未经授权缩小为 task_only、或仍有任何美术资产参考图处于 PENDING / FAIL / 未替换废弃状态，立即触发 `[E16: A3 Asset Completion Barrier Failure]`，禁止生成舞台定位图，必须回到 A3 补齐资产。禁止把某个 `video_task_id` 的局部 `coverage_status: PASS` 当作 A3 全阶段完成。
1. 重新读取 `故事板概要 — [集数][段落编号][场景名]`、`场景调度表 — [集数][段落编号][场景名]`、`空间真值调用中心 — [集数][段落编号][场景名]`，并定位其中的 `坐标与摄影机基准` 小节；若该小节不存在、坐标为裸数字 / 无键数组、缺少 X/Y/Z 键名或缺少 `reference_validity_chain`，必须回退 A2 修正，禁止继续生成舞台定位图。
2. 从当前段落场景调度表提取场景参考图、人物参考图、关键道具参考图，并解析为真实画布 image 节点或实际 `image_path`；三类资产必须写入 `Reference image paths` 与 `Reference Mention Map`，禁止只用自然语言描述代替真实路径。同时必须把本次通过的 `A3_SCOPE_MANIFEST.freeze_id` 写入 A4 派单载荷、table_node 顶层和 A0 当前 `video_task_mapping[video_task_id].source_a3_scope_manifest_freeze_id`；未写入该字段的 A4 视为无法证明 A3 完整性，禁止被 B1-B5 消费。
3. 将剧情范围、场景名、主要冲突、结尾衔接、角色坐标、道具坐标、`facing_target_xy`、`camera_facing`、镜头方向、朝向箭头、Eyeline Map、相对距离、运动路径、当前任务全部资产参考图路径写入 task_description；同时写入从同一组数值真值推导出的 `screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_direction_text`、`camera_screen_position_text`、`movement_direction_text`。
3A. **A4 下游消费展开锁 / A4 Consumer Expansion Lock**：A4 不是只产出可视鸟瞰图；它必须为 B1-B5 与 B6-B8 生产可复制的空间解释载荷。A4 `[MANDATORY DISPATCH PAYLOAD]`、A4 table_node 顶层、每个角色/道具行、A0 `video_task_mapping[video_task_id]` 与冻结记录中，必须写出一段可被下游原样展开的自然语言解释：`画面使用 100x100 xy 坐标系，左上/前后/屏幕方向以 source_coordinate_camera_baseline_section 为准；红/橙/黄...方形代表对应角色，红/橙/黄...圆形代表对应道具；紫白色短粗箭头从每个角色 stage_position_xy 指向 facing_target_xy，表达身体朝向和视线/注意力方向。` 随后必须逐项列出每个角色与道具的 `stage_position_xy`、`stage_position_xyz`、`facing_target_xy/xyz`、`screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_position_xyz`、`camera_target_xyz`、`camera_direction_text`、`camera_screen_position_text`、`focal_length_mm`、`eyeline`、`distance_relation`、`movement_path_xyz`、`movement_direction_text` 或道具方位字段。禁止只写“坐标见 table_node / 按舞台定位图 / 已冻结 A4”。缺该展开载荷时，A4 自身判定 FAIL，且不得被 B1-B5 消费。
4. 人物和道具的空间位置只以空间真值文档 / table_node 的文字坐标、朝向、自然语言方位字段和 Eyeline 为准；人物 / 道具参考图片只用于身份、轮廓、比例和道具类别识别，禁止覆盖 `stage_position_xy`、`facing_target_xy`、`camera_facing`、镜头方向或任何 `_text` 方位字段。
5. 若场景参考图是透视室内图，必须要求模型降维映射为 2D 鸟瞰平面，只提取墙壁、门窗和家具相对几何边界。
6. 必须从 A2 角色站位表、当前 A4 table_node 和 A0 `reference_requirements` 建立 `[Character Count Lock]`，并写入 task_description、table_node 顶层和 A0 当前 `video_task_mapping[video_task_id]`。该锁至少包含：`allowed_visible_characters`、`allowed_visible_character_count`、`allowed_character_nodes`、`forbidden_extra_people`、`character_count_lock_source`、`character_count_lock_status: PASS | FAIL`。合并人物参考图必须拆解为具体已声明角色写入 `allowed_visible_characters`；若下游为了槽位把多名角色合并成一个参考图，也不得把合并图解释为允许生成更多人物。
7. **A4 参考图数量硬锁 / Stage Map Reference Count Lock**：A4 派单前必须根据当前 `video_task_id` 动态计算 `expected_stage_map_reference_image_paths`，公式固定为：当前任务场景参考图 + `allowed_visible_characters` 对应的全部人物参考图 / 必要合并人物参考图 + 当前任务参与空间调度的全部关键道具参考图 / 必要合并道具参考图。`segment_full` 的 A3 完整资产范围只用于证明 A3 完成，不等于 A4 要加载全段所有资产；但当前任务内剧本明确可见、参与空间关系、承担对照或被角色持有的全部人物与道具都必须进入 A4，不得因为“主角/主道具”优先而裁掉配角、评审席人物、桌面方案组、随身资料、固定空间锚点道具等当前任务空间对象。必须在 `[MANDATORY DISPATCH PAYLOAD]`、A4 table_node 顶层和 A0 `video_task_mapping[video_task_id]` 同步写入：`expected_stage_map_reference_image_paths`、`expected_stage_map_reference_count`、`actual_stage_map_reference_image_paths`、`actual_stage_map_reference_count`、`stage_map_reference_exact_match_check.same_count / same_order / same_paths`、`forbidden_stage_map_reference_assets`。A4 只有在 `actual == expected` 且 `same_count == true`、`same_order == true`、`same_paths == true` 时才能调用 image agent；否则触发 `[E06: Reference Resolve Failure]`，不得只把参考图写成自然语言清单继续派单。禁止在 reference 规则中为具体项目硬编码固定数量；数量必须来自 A0/A1/A2/A3 对当前 `video_task_id` 的最新 ACTIVE 资产池与人物/道具空间真值。

## 画面要求

舞台定位图必须包含：90 度垂直俯视图、x / y 坐标网格、角色矩形色块、每个角色色块旁的中文角色全名标签文本、道具圆形色块、紫白色短粗朝向箭头、坐标指向文字。

**A4 角色/道具形状与颜色编码硬锁 / Shape-Color Encoding Lock**：所有允许可见人物必须用“方形 / 矩形色块”标记位置，所有关键道具必须用“圆形色块”标记位置，二者不得混用。人物颜色顺序固定为：红、橙、黄、绿、青、蓝、紫、粉、白；按 `allowed_visible_characters` 的顺序逐一绑定，一人一色，一旦写入 A4 table_node 与 Reference Mention Map，下游 B1-B5/B6-B8 必须原样继承，不得重新排序或重新配色。道具颜色顺序同样固定为：红、橙、黄、绿、青、蓝、紫、粉、白；按当前任务 `required_prop_tokens` / A4 table_node 道具行顺序逐一绑定，一道具一色。白色人物方块或白色道具圆形必须带深色描边。A4 table_node 顶层必须写入 `character_shape_color_map` 与 `prop_shape_color_map`，每个映射项至少包含：`name`、`token`、`shape: square|circle`、`color_name`、`color_index`、`stage_position_xyz`、`asset_image_path`、`label_text`。B1-B5 的 `[Stage Map Same-Source Spatial Payload]` 必须逐项继承这两个映射，黑白分镜虽然最终为纯黑白线稿，但必须在结构化文本中保留“某角色/道具在 A4 中的形状、颜色编号和坐标”，用于防止人物/道具错位或互换。

**角色全名保真锁 / Chinese Full Character Name Label Lock**：A4 舞台定位图中的可见角色标签必须直接使用剧本 / A0 / A2 中的中文角色全名。禁止把中文角色名改成中文短名、昵称、省略称、拼音首字母、英文缩写、英文代号、罗马字、identity_token 片段或任意非全名标签；例如禁止把多字中文全名缩短为单姓、职务词或机器代号。如果画面空间不足，必须调整排版、字号、引线、图面留白或标签位置来容纳中文全名，不得缩短角色名。该规则优先于“简写”“标签”“allowed_character_nodes”等所有字段名。

**人物数量锁画面要求**：角色矩形色块数量必须等于 `allowed_visible_character_count` 或 `allowed_character_nodes` 的显式数量；每个色块必须能回溯到 `allowed_visible_characters` 中的一个已声明角色或已声明合并角色节点。禁止出现未登记人物色块、额外人形、群众剪影、额外评委、额外工作人员、路人、游客、背景旁观者或由场景参考图自动补出的任何人。若需要表现评审席背景，只能使用已列入 `allowed_visible_characters` 的评审角色，不得用匿名人物填充空间。

模型参数：`image2 / 1k / 16:9 / medium`（画质：中）。A4 派单载荷、冻结记录、QC 记录与实际生成 metadata 必须显式写入：

```yaml
model: gpt-image-2
model_alias: image2
resolution: 1k
quality: medium
aspect_ratio: 16:9
```

2. 结构化坐标位置表节点（table_node），锁死角色和道具的几何坐标、朝向、Eyeline、镜头方向、相对距离、运动路径、形状颜色编码和自然语言方位字段。table_node 顶层必须包含：`table_node_version`、`generated_at`、`source_a3_scope_manifest_freeze_id`、`a3_completion_status: PASS`、`source_space_truth_version`、`source_space_truth_node`、`source_coordinate_camera_baseline_section: 坐标与摄影机基准`、`video_task_id`、`allowed_visible_characters`、`allowed_visible_character_count`、`allowed_character_nodes`、`forbidden_extra_people`、`character_count_lock_status`、`character_shape_color_map`、`prop_shape_color_map`，用于 B1 比对 A3 完整性、版本号 / 时间戳 / 空间真值来源、人物数量锁和形状颜色映射。每个角色行必须包含：`identity_token`、`asset_ref_id`、`asset_image_path`、`shape: square`、`color_name`、`color_index`、`stage_position_xy`、`stage_position_xyz`、`facing_target_xy`、`facing_target_xyz`、`screen_position`、`screen_direction_text`、`spatial_direction_text`、`facing_direction_text`、`camera_facing`、`camera_position_xyz`、`camera_target_xyz`、`camera_direction_text`、`camera_screen_position_text`、`focal_length_mm`、`eyeline`、`distance_relation`、`movement_path`、`movement_path_xyz`、`movement_direction_text`、`state_action`。每个道具行必须包含：`prop_token`、`asset_ref_id`、`asset_image_path`、`shape: circle`、`color_name`、`color_index`、`stage_position_xy`、`stage_position_xyz`、`prop_spatial_direction_text`、`owner_character`、`attachment_point`、`visibility_state`、`movement_path`、`movement_path_xyz`、`prop_movement_direction_text`；若该道具来自 A0 `performance_substitution_plan` 的静态结果道具，还必须包含 `substitution_result_state` 与对应 `risk_id`。所有二维坐标字段必须是 `{"x": number, "y": number}`，所有三维坐标字段必须是 `{"x": number, "y": number, "z": number}`；A4 table_node 中每个角色和道具都必须同时写入 `stage_position_xyz`，平面对象默认 `z: 0`，摄影机 / 多层空间使用真实高度值。禁止裸数字、无键数组、`x,y` 字符串或只写二维而缺少可传递的三维字段。

## 空间防撞

生成 table_node 时必须执行空间像素防撞立体校验。同一高度层级的角色或道具不得共享完全相同的 `(x, y)`。若涉及阁楼、楼梯、横梁等多层空间，允许 `(x, y)` 相同，但必须用 `stage_position_xyz` 或 `Z-index` 标明高度层级，例如 Z=1 一楼、Z=2 二楼。未隔离高度层级且坐标完全重合，判定 FAIL。

## FAIL
